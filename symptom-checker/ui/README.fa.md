# رابط نمایشی فاز ۳ — همیار نشانه‌ها (منتشر نشده)

این پوشه یک **نمونهٔ نمایشی داخلی** است: صفحه‌ای مستقل و آفلاین که همان موتور فاز ۲ را در مرورگر اجرا می‌کند تا صاحب سایت و تیم، رفتار پرسش‌نامه، هشدارها و کارت‌ها را ببینند. هیچ بخشی از آن به وردپرس، به hamyarjarahi.ir یا به هیچ سروری وصل نیست.

- **صفحه چیست:** `index.html` + `styles.css` + `app.js` (کنترل‌گر) + `view-model.js` (توابع خالص نمایش).
- **داده از کجا می‌آید:** `docs/symptom-checker/phase-1/knowledge-bundle.v1.json` و `symptom-checker/engine/data/evidence-map.v1.json`؛ هر دو با مسیر نسبی و فقط از همان مخزن بارگذاری می‌شوند.
- **موتور:** `symptom-checker/engine/src/engine.js` (بازاستفاده، بدون تغییر).

## اجرا

بارگذاری ماژول‌های ES با `file://` کار نمی‌کند؛ باید از ریشهٔ مخزن سرو شود تا مسیرهای نسبی داده هم درست باز شوند:

```sh
cd symptom-checker/ui
npm run serve            # python3 -m http.server 8080 --bind 0.0.0.0 --directory ../..
# سپس در مرورگر: http://localhost:8080/symptom-checker/ui/
```

## آزمون

```sh
cd symptom-checker/ui && node --test        # ۱۲ آزمون واحد view-model، بدون وابستگی
npm install --no-save jsdom                 # فقط برای آزمون سرتاسری
node tests/ui-smoke.mjs --all               # ۱۲ سناریو × ۲۹ بررسی (۳۲ در سناریوی تناقض)
# سناریوهای حاشیه‌ای فاز ۵ روی همان رابط:
# مسیرها نسبت به ریشهٔ مخزن خوانده می‌شوند:
node tests/ui-smoke.mjs --scenarios docs/symptom-checker/phase-5/scenarios-adversarial.v1.json --all
```

`tests/ui-smoke.mjs` صفحهٔ واقعی را در jsdom بالا می‌آورد، پرسش‌نامه را مثل یک کاربر با کلیک روی همان ورودی‌ها پاسخ می‌دهد و بعد نتیجهٔ نمایش‌داده‌شده را با اجرای مستقیم موتور روی همان پاسخ‌ها مقایسه می‌کند (پوشش، کارت‌ها، هشدارها، ترتیب هشدار فوری، جای نوار هشدار پیش از کارت‌ها، متن کامل هر هشدار)، ویرایش/بازگشت و شروع دوباره را می‌سنجد و محرمانگی را می‌شمارد: فقط دو `fetch` هم‌مبدأ GET بدون بدنه، حافظهٔ محلی/نشستی و کوکی خالی، `indexedDB` دست‌نخورده، نبود فرم ارسالی و نبود ناوبری. اگر سؤالی در سناریو پاسخ نداشته باشد، گزینهٔ بی‌طرف (`نمی‌دانم`، سپس `خیر`) انتخاب می‌شود. اگر jsdom نصب نباشد، فایل با پیام `SKIP` و کد خروج ۰ رد می‌شود. در نسخهٔ ۰.۱.۱ گروه «پاسخ متناقض» دکمهٔ «این دو پاسخ را اصلاح کنم» دارد؛ آزمون سرتاسری بررسی می‌کند که این دکمه فهرست پاسخ‌ها را باز کند و هر دو ردیف متناقض نشانه بخورند، و آزمون دیگری مطمئن می‌شود این دکمه فقط وقتی تناقض واقعی هست ظاهر شود.

## آنچه این نمونه ادعا نمی‌کند

- **نه تشخیص، نه احتمال، نه درصد.** خروجی فقط «موضوع‌های مرتبط» است و آزمون‌ها وجود واژه‌های احتمال/امتیاز/درصد در متن نتیجه را رد می‌کنند.
- **آزمون در مرورگر واقعی انجام نشده است.** بررسی‌ها در jsdom است؛ چیدمان، RTL، موبایل و صفحه‌خوان واقعی هنوز بازبینی انسانی لازم دارد.
- **داده پیش‌نویس است.** متن سؤال‌ها و هشدارها `pending_team_review` است و نگاشت مقاله‌ها `needs_live_verification`؛ در نتیجه هیچ لینکی در کارت‌ها نمایش داده نمی‌شود.
- **محدودیت شناخته‌شده:** اگر تنها نشانهٔ گزارش‌شده «سوزش/تکرر ادرار» باشد و بقیه «نمی‌دانم» یا بی‌پاسخ بمانند، پوشش `insufficient` می‌شود و عمداً هیچ کارتی نمایش داده نمی‌شود. این رفتار موتور است، نه اشکال نمایش؛ پیش از نمایش عمومی باید تصمیم تیم باشد.
