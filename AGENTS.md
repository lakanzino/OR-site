# Repository guidance

## Booking project journal

When working on the surgeon appointment-booking project, update `docs/booking/BOOKING-PROJECT-JOURNAL.fa.md` in the same change at the end of each stage or meaningful decision, test result, blocker, or scope change. Follow its maintenance procedure: preserve history, identify incomplete or simulated work, link verifiable evidence, and recalculate the approximate weighted progress with a brief rationale. Do not record patient information, credentials, or other private data. The journal's percentage is an estimate, not a release-readiness claim. Stage 3 was formally closed by the user; Stage 4 migration work and drafting a staging QA plan are authorized on the session branch. Report the plan and await the user's approval before staging execution. Never contact, install on, migrate, or modify the live site; production deployment requires a separate explicit authorization after all Go/No-Go debts are resolved.
