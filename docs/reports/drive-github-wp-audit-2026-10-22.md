# گزارش تطبیق Google Drive ↔ GitHub ↔ وردپرس زنده

- **تاریخ بررسی:** ۳۰ مهر ۱۴۰۵ — 2026-10-22
- **مخزن:** https://github.com/lakanzino/OR-site (شاخه‌ی `main`، عمومی)
- **مرجع سایت زنده (طبق قانون آینه):** پوشه‌ی «همیار جراحی — آینه‌ی سایت منتشرشده (Live Mirror)» در Google Drive
- **سایت:** https://hamyarjarahi.ir

> روش: فهرست کامل فایل‌های Drive (تاریخ، حجم، نسخه) با محتوای مخزن در `HEAD` مقایسه شد. فایل‌های متنی Drive خوانده شد؛ فایل‌های باینری (ZIP/WebP) فقط از نظر نام، حجم و تاریخ مقایسه شدند، چون این محیط اجازه‌ی دانلود باینری از Drive را ندارد.

## ۱) خلاصه‌ی حکم

| پرسش | پاسخ |
|---|---|
| Drive و GitHub یکسان‌اند؟ | **نه.** GitHub حدود ۵ نسخه از قالب فرزند عقب است و هیچ‌کدام از محتوای زنده (صفحه/مقاله/تصویر/بسته) را ندارد. |
| GitHub به وردپرس وصل است؟ | **نه.** هیچ اتصال فنی (Actions، وبهوک، SFTP/SSH، افزونه، WP-CLI) وجود ندارد؛ استقرار کاملاً دستی با ZIP است. |
| آیا سایت زنده با Drive می‌خواند؟ | طبق مانیفست و «وضعیت استقرار»: **بله** (آخرین راستی‌آزمایی ۳۰ مهر ۱۴۰۵؛ قالب فعال 0.9.1). این ادعا از داخل این محیط قابل تست مستقیم نبود. |

## ۲) قالب‌ها

| مورد | Drive / سایت زنده | GitHub (`main`) | وضعیت |
|---|---|---|---|
| قالب والد `lax-theme` | 1.0.1 | 1.0.1 | ✅ یکسان |
| قالب فرزند `lax-theme-child` | **0.9.1** (ZIP نصب: `lax-theme-child-install-0.9.1.zip`) | **0.4.0** (`style.css: Version: 0.4.0`) | ❌ اختلاف ۵ نسخه |
| تگ/ریلیز | 0.7.0 / 0.8.0 / 0.8.1 / 0.9.0 / 0.9.1 | فقط `child-v0.4.0` | ❌ عقب‌ماندگی |
| برند و دامنه | همیار جراحی / hamyarjarahi.ir | همان (ADR-010 در `docs/DECISIONS.md`) | ✅ یکسان |

یادداشت نسخه‌ها طبق Drive: 0.8.0 → 0.8.1 (ایمپورتر تک‌مقاله + رفع باگ نام یکتای تصویر) → 0.9.0 **منسوخ** (خطای مهلک فرانت `wp_delete_nav_menu_item`) → **0.9.1 مستقر و تأییدشده** (طراحی ریسپانسیو صفحه‌ی اول، کارت تصویر+تیتر، نوارهای باریک، فوتر با لوگو، حذف سیاست نشریه و انتقال آن به زباله‌دان، مهاجرت در `try/catch`). هیچ‌کدام از این تغییرات در GitHub نیست.

## ۴) اسناد پروژه

- اسناد داخل مخزن (`docs/`، ۱۶ فایل) تا ۲۰۲۶-۱۰-۱۹/۲۰ به‌روزند: ADR تا ADR-010، چنج‌لاگ تا 0.4.0، نقشه‌ی محتوای نسخه‌ی ۱.
- اسناد Drive از ۲۰۲۶-۱۰-۲۱/۲۲ جلوترند: `CONTENT-ROADMAP-v2-MERGED`، `ARTICLE-STYLE-GUIDE`، `PERFORMANCE-REPORT`، مانیفست آینه، قانون آینه، راهنمای ایمپورت مقاله، وضعیت استقرار. **هیچ‌یک در GitHub نیست.**
- `docs/PROJECT-CHANGELOG.md` مخزن هنوز می‌گوید قالب فرزند 0.4.0 «آماده و تست‌شده» است — با واقعیت زنده (0.9.1) ناسازگار.

## ۵) اتصال GitHub ↔ وردپرس (بررسی فنی)

| نشانه‌ی اتصال | نتیجه |
|---|---|
| GitHub Actions / workflow | ❌ `total_count: 0` |
| وبهوک استقرار (Deploy hook) | ❌ نه در مخزن، نه در تنظیمات قابل‌مشاهده |
| اسکریپت/تنظیم SFTP، SSH، rsync، FTP | ❌ هیچ فایلی در مخزن نیست |
| افزونه یا mu-plugin همگام‌ساز | ❌ پوشه‌ی `plugins/` وجود ندارد |
| WP-CLI / `bin/` | ❌ وجود ندارد (فقط در سند پرامپت اولیه پیشنهاد شده) |
| Release به‌عنوان کانال نصب | ✅ تنها مسیر واقعی: دانلود ZIP از Releases و آپلود دستی در پیشخوان |
| آخرین push مخزن | ۲۰۲۶-۱۰-۲۰ ۰۱:۴۸ UTC (کل تاریخچه: **۱ کامیت**) |
| آخرین تغییر آینه در Drive | ۲۰۲۶-۱۰-۲۲ ۰۲:۱۲ UTC |

**نتیجه:** استقرار روی هاست کاملاً دستی و بیرون از GitHub است. هر تغییری که پس از ۲۰ مهر انجام شده (نسخه‌های 0.5.0 تا 0.9.1 + محتوای زنده) فقط در Drive و روی هاست است؛ GitHub «منبع حقیقت» نیست.

## ۶) محدودیت‌های همین بررسی

- دسترسی خروجی این محیط فقط به `github.com` است؛ `drive.google.com` و `hamyarjarahi.ir` در دسترس نیستند. بنابراین:
  - وضعیت HTTP سایت زنده مستقیم تست نشد (تکیه بر مانیفست Drive).
  - فایل‌های باینری Drive (ZIP قالب 0.9.1، ZIP بسته‌های مقاله، WebP) قابل انتقال به مخزن نبودند؛ فقط فایل‌های متنی قابل خواندن/انتقال‌اند.

## ۷) اقدام‌های پیشنهادی (به ترتیب اولویت)

1. **کد 0.9.1 را به مخزن برگردانید** — ZIP `lax-theme-child-install-0.9.1.zip` را در فضای کاری آپلود کنید تا محتوایش روی `themes/lax-theme-child/` استخراج، با 0.4.0 دیف و کامیت شود؛ سپس تگ `child-v0.9.1` و Release ساخته شود.
2. **آینه‌ی متنی محتوا** — ۵ مقاله + ۶ صفحه + مانیفست/قانون آینه در مسیر `content/live-mirror/` مخزن قرار گیرد (قانون آینه: نسخه‌ی داخل آینه دقیقاً نسخه‌ی زنده است).
3. **بستن شکاف مستندات** — افزودن `CONTENT-ROADMAP-v2-MERGED`، `ARTICLE-STYLE-GUIDE`، `PERFORMANCE-REPORT-2026-10-21` و به‌روزرسانی `PROJECT-CHANGELOG` تا 0.9.1.
4. **اتصال واقعی GitHub به وردپرس** (اختیاری، پیشنهاد): یک workflow استقرار با SFTP/SSH روی هاست یا یک افزونه‌ی به‌روزرسانی از GitHub Release، تا «منبع حقیقت» یکی شود و آپلود دستی حذف شود.
