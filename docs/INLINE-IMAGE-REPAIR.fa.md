# رفع نمایش alt به‌جای تصویر داخل مقالات جراحی — 0.15.1

تاریخ: ۲۰۲۶-۱۰-۲۷ · وضعیت: بستهٔ نصب ساخته و محلی آزموده شده؛ روی سایت زنده اجرا نشده است.

## علت مستند

۹ مقالهٔ overview جراحی در مجموع ۱۸ تصویر دارند. در HTML بسته‌ها، آدرس تصویر `assets/<name>.webp` است. این آدرس برای بسته درست است، اما در وردپرس باید به URL فایل واقعی در کتابخانهٔ رسانه تبدیل شود؛ مرورگر پوشهٔ ZIP را نمی‌شناسد.

اصلاح اولیه در سورس 0.15.0 شاخهٔ `arena/43a7ddbf-or-site` بود، ولی `releases/lax-theme-child.zip` و `releases/orsite-release.json` همچنان 0.14.0 بودند. وجود کد در شاخه یا تحویل ZIP مقاله به‌تنهایی به معنی نصب ایمپورتر جدید نیست. نسخهٔ نصب‌شده و URL خراب واقعی سایت در این نشست در دسترس نبود؛ این علت از فایل‌های مخزن اثبات می‌شود، نه از مشاهدهٔ مستقیم سایت.

## راه کوتاه برای مقالات موجود — بدون ایمپورت مجدد متن

1. پیش از نصب، از فایل‌های قالب و دیتابیس سایت نسخهٔ پشتیبان بگیرید.
2. از **نمایش ← پوسته‌ها ← افزودن ← بارگذاری پوسته**، فایل جاری `releases/lax-theme-child.zip` را نصب و «جایگزینی نسخهٔ فعلی» را تأیید کنید. نسخه باید **0.15.1** باشد؛ قالب والد تغییر نکرده است.
3. به **جراحی‌ها ← ترمیم تصاویر داخل مقاله** بروید. صرف بازکردن صفحه هیچ تغییری در سایت نمی‌دهد.
4. کنار مقاله‌ای که مسیر محلی دارد، **«ترمیم فقط تصاویر این مقاله»** را بزنید. هر مقاله جدا اجرا می‌شود تا سقف زمان هاست مسئله نشود.
5. مقاله را باز کنید: باید هر دو تصویر دیده شوند؛ URL تصویر باید زیر کتابخانهٔ رسانه باشد، نه `assets/…` یا `/surgery/<slug>/assets/…`. خود URL تصویر را در زبانهٔ تازه باز کنید و دریافت فایل را بررسی کنید.
6. اگر خروجی کش‌شده است، کش LiteSpeed و CDN را پاک کنید و یک بار بدون کش مرورگر بارگذاری کنید.

ابزار فقط `src` تصاویر شناخته‌شده را تغییر می‌دهد؛ عنوان، متن، alt، کپشن، تصویر شاخص و وضعیت انتشار را جایگزین نمی‌کند. نسخهٔ متن قبل از ترمیم در متای `_hj_inline_repair_original` نیز نگهداری می‌شود. در صورت شکست آپلود، متن ذخیره نمی‌شود؛ خطای ذخیره هم به‌عنوان موفقیت گزارش نمی‌شود. اجرای دوباره رسانهٔ تکراری نمی‌سازد.

فایل هر ۱۸ تصویر داخل خود قالب است؛ نه دانلود از GitHub لازم است، نه آپلود ۹ ZIP مقاله. تصاویر خارجی یا مسیر ناشناخته حدس زده نمی‌شوند. اگر شمار تصاویر محلی صفر بود ولی تصویر هنوز شکسته بود، URL مقاله و `src` واقعی تصویر لازم است؛ این می‌تواند مورد متفاوتی مانند فایل حذف‌شده یا محدودیت هاست باشد.

## آزمون و ساخت مجدد

```sh
php tests/inline-images.php
python3 tools/content-lint.py
python3 tools/build-theme-release.py
```

آزمون PHP با API شبیه‌سازی‌شدهٔ وردپرس و فایل واقعی انجام می‌شود؛ تست سایت زنده یا دیتابیس وردپرس واقعی نیست. پوشش: هر ۹ مقاله و ۱۸ تصویر، حفظ متن/alt/کپشن/تصویر شاخص/وضعیت، اجرای تکراری، خرابی فایل با هش قدیمی، خطای آپلود و ذخیره، عدم دسترسی، مسیر خارجی و جلوگیری از خروج از پوشه. آزمون‌ها در PHP 7.4 و 8.5 اجرا شدند.

`tools/build-theme-release.py` یکسان‌بودن نسخه در هدر، ثابت PHP و readme، وجود و برابری هر ۱۸ تصویر و سلامت ZIP را کنترل می‌کند؛ مانیفست و ZIP از همان سورس ساخته می‌شوند. `published_at: null` یعنی این خروجی هنوز یک GitHub Release رسمی منتشرشده نیست.
