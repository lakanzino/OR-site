# ابزار: symptom-checker-author — نسخهٔ 0.1.0

**پوشه = نام ابزار = نسخه.** مسیر سورس: `tools/symptom-checker-author/` · نخستین نسخه، از فاز ۳ رانبوک v2.
به‌عنوان ابزار توسعه منتشر می‌شود، نه همراه افزونه.

## چه می‌کند

بیماری تازه را **فقط با داده** وارد ماتریس «بیماری × نشانه» می‌کند و پیش از نوشتن بسته، سه سد را اجرا می‌کند.

## خط لوله

```text
v1 ──(v1_to_v2.py)──▶ v2.base.json ──(+ authoring/)──▶ v2.json
```

## دستورها

| دستور | کار |
| --- | --- |
| `validate` | schema + ارجاع + پوشش + متن راهنما + **موتور واقعی** |
| `overlap [--json]` | جفت‌های هم‌پوشان + جداکنندهٔ قابل‌پرسش؛ بدون جداکننده ⇒ کد ۱ |
| `gen-scenarios [--out]` | شخصیت `typical` برای هر بیماری |
| `report [--out]` | پوشش نشانه‌ها و بیماری‌های بدون جداکننده |
| `build-bundle [--check] [--no-bump] [--date]` | ساخت/بررسی بسته، نسخهٔ minor، `change_notes` |
| `add-condition <id> --name …` | اسکلت بیماری (نام دیگر: `scaffold-condition`) |
| `add <kind> --file …` | افزودن یک فایل داده به workspace |

## سه سد

1. `validate_v2.py` — ساختار، ارجاع، پوشش، نسخه.
2. قواعد نویسندگی — ≥۳ ردیف پروفایل، ≥۱ `typical`، منبع روی هر ردیف، متن راهنما برای هر گزینه، شناسهٔ یکتا.
3. `load-bundle.js` موتور — بسته‌ای که موتور نمی‌پذیرد، نوشته نمی‌شود.

## چه چیزی را تضمین می‌کند

- بسته فقط از پایه + داده ساخته می‌شود؛ دست‌نویس ممنوع و با `--check` گرفته می‌شود.
- شکاف نشانهٔ **تازه** خطاست (کد ۱)؛ شکاف ارثی هشدار می‌ماند.
- شخصیت ساخته‌شده قاعدهٔ پوشش (مثل بارداری) را بی‌خبر فعال نمی‌کند.

## چه چیزی را **نه**

- پاسخ واقعی کاربر اجرا نمی‌کند و چیزی ذخیره نمی‌کند.
- مقاله به بیماری وصل نمی‌کند؛ حدس ممنوع.
- بیماری موجود را حذف یا بازنویسی نمی‌کند.

## آزمون

`python3 -m unittest discover -s tools/symptom-checker-author -p 'test_*.py'` — ۱۷ آزمون (بازتولیدپذیری، ایدمپوتنسی، هر شش رد کردن، پذیرش کوله‌سیستیت).
