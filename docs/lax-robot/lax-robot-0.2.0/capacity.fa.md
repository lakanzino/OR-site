# ظرفیت: امروز چند بیماری، و تا کجا؟

**نسخهٔ سند:** `lax-robot-0.2.0` · ۳۱ اکتبر ۲۰۲۶ · اعداد از خودِ بستهٔ دانش درآمده‌اند، نه از حدس.

---

## ۱. عدد امروز

| چیز | بستهٔ تحویل‌شدنی (`0.2.0-draft`) | مجموعهٔ پذیرش کوله‌سیستیت (`0.3.0-draft`) |
| --- | --- | --- |
| بیماری | **۵** (`app`, `kidney_stone`, `kidney_infection`, `urinary_tract`, `gastroenteritis`) | **۶** (+ `chole`) |
| نشانه | ۲۷ | ۲۸ |
| نشانهٔ قابل‌پرسش | ۲۵ (دو نشانه هیچ گزینه‌ای ندارد و `not_covered` می‌مانند) | ۲۶ |
| پرسش | ۱۷ | ۱۸ |
| گزینه | ۷۱ | ۷۴ |
| ردیف پروفایل | ۴۳ | ۴۹ |

## ۲. سقف واقعی، «تعداد بیماری» نیست

سه سقف متفاوت وجود دارد و باید از هم جدا شوند:

### الف) سقف حالات پاسخ (بی‌معنا بزرگ)

حاصل‌ضرب تعداد گزینه‌های هر پرسش (با احتساب ترکیب‌های چندگزینه‌ای):
**≈ ۷٫۱ × ۱۰¹⁵** مسیر پاسخ ممکن. این عدد نشان می‌دهد موتور هیچ‌جا «پر» نمی‌شود؛ محدودیت جای دیگری است.

### ب) سقف امضاهای شواهد (یعنی چند «تصویر بالینی» متمایز)

حاصل‌ضرب مجموعه‌های شواهد متمایز هر پرسش:
**۶۷٬۱۰۸٬۸۶۴ = ۲²⁶** تصویر متمایز با ۲۶ نشانهٔ قابل‌پرسش امروز.

یعنی از نظر داده، **دو بیماری هرگز با هم قاطی نمی‌شوند مگر امضایشان یکی باشد** — و `overlap` دقیقاً همین را می‌گیرد. برای همین «سقف بیماری» عملاً یعنی «چند بیماری می‌توان با امضای متمایز نوشت».

### ج) سقف تحمل کاربر (سقف واقعی)

کاربر نمی‌تواند ۴۰ پرسش ببیند. امروز ترتیب ثابت است و همهٔ پرسش‌های نمایان پرسیده می‌شوند؛ پس **سقف عملی = تعداد پرسش‌هایی که آدم تحمل می‌کند**.

## ۳. هزینهٔ افزودن هر بیماری

| وضعیت بیماری تازه | هزینهٔ پرسش |
| --- | --- |
| همهٔ نشانه‌هایش از قبل پرسیده می‌شوند (مثل `urinary_tract`) | **۰ پرسش تازه** |
| یک نشانهٔ کلیدی ندارد (مثل کوله‌سیستیت ← «درد بعد از غذای سنگین») | **۱ پرسش** (و ۱ نشانه) |
| دو نشانهٔ اختصاصی دارد | ۱–۲ پرسش |
| نشانه‌هایش با همهٔ بیماری‌ها مشترک است و هیچ جداکنندهٔ قابل‌پرسشی ندارد | **قابل افزودن نیست** تا پرسش تازه ساخته شود (`overlap` می‌ایستد) |

قاعدهٔ سرانگشتی با ترتیب ثابت: **حدود ۱ تا ۱٫۵ پرسش برای هر بیماری تازه**؛ با انتخاب تطبیقی (فاز ۴) رشد به **≈ log₂(N)** نزدیک می‌شود و برای ۳۰ بیماری حدود ۵–۷ پرسش کافی است.

## ۴. پنجرهٔ عملی

| محدوده | وضعیت |
| --- | --- |
| ۵ تا ~۱۰ بیماری | **راحت**؛ ۱۵–۲۰ پرسش، بدون پرسش تکراری، بدون نیاز به فاز ۴ |
| ~۱۰ تا ~۲۰ بیماری | **ممکن** ولی ترتیب ثابت به ۲۵–۳۰ پرسش می‌رسد؛ کاربر خسته می‌شود |
| ~۲۰ تا ~۴۰ بیماری | **فاز ۴ لازم است** (انتخاب پرسش تطبیقی)، وگرنه تجربهٔ کاربر خراب می‌شود |
| بیشتر از ~۴۰ در یک خوشه | باید خوشه را شکست (شکم، قفسهٔ سینه، …) — هر خوشه بستهٔ دانش مستقل با `scope` خودش (فاز ۶) |
| سقف سخت داده | ۲^N با N نشانهٔ قابل‌پرسش؛ امروز ۶۷ میلیون — عملاً بی‌نهایت |

**پاسخ کوتاه:** امروز **۶ بیماری** نوشته شده و **۵** تحویل می‌شود. با همین موتور و همین پرسش‌ها، **تا حدود ۲۰ بیماری شکمی** بدون هیچ تغییر معماری جا می‌شود؛ از آن به بعد فاز ۴ (تطبیقی) شرط می‌شود، و برای خوشه‌های دیگر (قفسهٔ سینه، سر و گردن) بستهٔ دانش جدا لازم است — که ساختار امروز پشتیبانی می‌کند.

## ۵. چه چیزی ظرفیت را واقعاً می‌بندد (به ترتیب اهمیت)

1. **بازبینی محتوا** — هر بیماری تازه یک پروفایل با منابع می‌خواهد که کسی باید تأیید کند.
2. **جداکنندهٔ قابل‌پرسش** — بیماری بدون نشانهٔ اختصاصی، فقط سربار است.
3. **طول پرسش‌نامه** — نه تعداد بیماری.
4. **کیفیت منبع** — NIDDK/NHS کافی است، ولی برای موارد ایرانی باید منابع بومی هم اضافه شود.

## ۶. اندازه‌گیری، نه احساس

هر بار که بیماری تازه اضافه می‌شود، همین سه دستور عدد تازه می‌دهند:

```sh
A=tools/symptom-checker-author/author.py
python3 $A --workspace docs/symptom-checker/authoring/examples/cholecystitis report --out /tmp/r.md   # پوشش و جفت‌ها
python3 $A --workspace docs/symptom-checker/authoring/examples/cholecystitis gen-scenarios --out /tmp/s # یک شخصیت per بیماری
python3 $A --workspace docs/symptom-checker/authoring/examples/cholecystitis validate                    # شکاف = خطا
```
