# مرحلهٔ ۵.۲۵ — آزمون ویرایش حین ذخیره بر سرور واقعی دورریختنی

آزمون مرحلهٔ ۵.۲۴ با barrier تزریق خطای موجود و محدود به CI، writer واقعی برنامه را پس از گرفتن mutex پزشک متوقف می‌کند. Chromium احرازشده متن و ساعت را هنگام انتظار ویرایش و تلاش مجدد ارسال می‌کند. پس از آزادسازی، snapshot و نام باید مقادیر زمان ارسال، و صفحه و پیام باید ویرایش جدید ذخیره‌نشده را نشان دهند؛ سپس ذخیرهٔ صریح با revision جدید بررسی می‌شود. هیچ تأخیر تصادفی برای ترتیب رویدادها استفاده نمی‌شود. [بحث Playwright](https://github.com/microsoft/playwright/issues/31631) تفکیک درخواست، پاسخ و ترتیب را روشن می‌کند. تنها ابزار CI تغییر کرده؛ نتیجهٔ [CI رزرو 42415895217](https://github.com/lakanzino/OR-site/actions/runs/42415895217) و [MariaDB 42415895220](https://github.com/lakanzino/OR-site/actions/runs/42415895220) موفق است.

کاربر آزمایشی، hook و DB صرفاً در CI دورریختنی‌اند؛ ترتیب‌ها و اتصال اینترنت/سایت واقعی، نوشتن هم‌زمان بازیگر دیگر، قطع COMMIT، ACF واقعی، اتمی‌بودن کل فرم و idempotency اثبات نشده‌اند. تغییر فرم بدون تغییر دادهٔ قابل ارسال ردیابی نمی‌شود. مهاجرت و سه بدهی اصلی باز و پیشرفت **۷۵٪ ثابت** است.
