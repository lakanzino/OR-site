# پایان انتقال الگوی backend مرحلهٔ ۲ — برای بازبینی کارفرما

الگوی تأییدشدهٔ مرحلهٔ ۲ به فایل‌های واقعی افزونه روی شاخهٔ کاری منتقل شده و آزمون‌های مشخص‌شدهٔ یکپارچه روی همان فایل‌ها در CI سبز شده‌اند. این گام **Stage 3 نیست** و به معنی آماده‌بودن نصب، انتشار یا فعال‌سازی روی سایت نیست. سایت زنده تغییر نکرده است.

## تفاوت fixture و فایل‌های افزونه

| موضوع | fixture تأییدشدهٔ Gate 2 | ادغام روی شاخه |
|---|---|---|
| داشبورد | کپی افزونه با یک خط جایگزین‌شده | `plugins/hamyar-doctors/includes/dashboard.php` مستقیماً `hj_booking_save_schedule` را فراخوانی می‌کند؛ کپی ACF/meta پس از commit و best-effort است. حالت پیش‌فرض غیرفعال رفتار سابق را نگه می‌دارد. |
| ذخیره و رزرو | `hjt_hjb_spike_*`، زمان ثابت و API صرفاً آزمایشی | `includes/appointments.php` و `includes/appointment-schedule.php`؛ نام جدول با prefix وردپرس ساخته می‌شود، ساعت واقعی و `wp_timezone()` به کار می‌روند و horizon نمونه ۳۰ روز است. |
| snapshot | جدول دارای `doctor_id`, `revision`, `rows_json`, `rows_hash` | همان ساختار منبع یگانهٔ اسلات و ساخت رزرو است؛ متای نمایشی در مسیر اسلات/رزرو خوانده نمی‌شود و hash/ساختار نامعتبر fail-closed است. |
| تراکنش | `wpdb` subclass آزمایشی با اتصال جداگانه | اتصال مستقل `HJ_Booking_Transaction_DB` از reconnect خودکار جلوگیری می‌کند؛ کلید قفل پزشک برای ذخیرهٔ برنامه، تنظیمات، اسلات، ساخت و تغییر وضعیت مشترک است. timeout/deadlock پیش از commit با حداکثر سه تلاش محدود و نتیجهٔ commit نامعلوم بدون retry کور برمی‌گردد. |
| رزرو | تاریخ، حساب و endpoint محدود به CI | توابع داخلی افزونه شماره و checksum کد ملی را اعتبارسنجی و جزئیات را در همان تراکنش ثبت می‌کنند؛ کلید idempotency با دادهٔ درخواست و هویت متصل است. endpointهای HTTP به کاربر نهایی اضافه نشده‌اند؛ adapter موجود فقط در MU-plugin دورریختنی تست است. |
| نصب و فعال‌سازی | جدول‌های آزمایشی ایجادشده در CI | قابلیت از ابتدا خاموش است؛ migration نسخهٔ ۱ فقط با فراخوانی صریح و مجوز مدیر انجام می‌شود و فعال‌سازی خودکار یا UI ندارد. پیکربندی هر پزشک نیز پیش‌فرض غیرفعال است. |

## شواهد

- [CI یکپارچهٔ فایل‌های افزونه — 42138876067](https://github.com/lakanzino/OR-site/actions/runs/42138876067)، commit `2cae7d8`: WordPress 7.1.4، PHP 8.4 و MariaDB 11.4 دورریختنی. شاخهٔ افزونه با symlink مستقیماً بارگذاری شد؛ هیچ بازنویسی یا patch روی فایل اصلی `dashboard.php` و `appointments.php` اعمال نشد. MU-plugin فقط endpoint تست، barrier و تزریق KILL را فراهم می‌کند.
- همان اجرا شامل nonce/مالکیت داشبورد، ذخیره‌های هم‌زمان، هشت بیمار هم‌زمان با بستن ساعات، هر دو ترتیب کنترل‌شدهٔ قفل، رد رزرو پس از بستن، KILL پیش از commit، بستن اتصال DB و socket HTTP پس از commit، replay هم‌زمان کلید idempotency، timeout و retry محدود، لغو/رزرو مجدد، رد ورودی نامعتبر و رد snapshot با hash خراب است. اثرات و شناسه‌ها در DB بررسی شدند.
- [CI سازگاری افزونه — 42138513977](https://github.com/lakanzino/OR-site/actions/runs/42138513977)، commit `fe26963`: ماتریس MariaDB مربوط به افزونه و ابزارهای موجود سبز است. [CI الگوی پیشین — 42137379366](https://github.com/lakanzino/OR-site/actions/runs/42137379366) همچنان شاهد fixture اولیه است، نه جایگزین آزمون فایل‌های افزونه.

## محدودیت‌های صادقانه و موارد پیش از انتشار

- بستهٔ `hamyar-doctors-0.3.18.zip` فقط برای یکسانی سورس و تست بسته ساخته شده است؛ **برای نصب یا انتشار تأیید نشده است**. هیچ deployment یا migration روی سایت زنده انجام نشده است.
- شکست کپی نمایشی با جلوگیری از نوشتن meta شبیه‌سازی شد، نه `update_field` ناموفق یا ACF Pro واقعی. ACF مرجع رزرو نیست؛ اما نمایش می‌تواند کهنه شود. outbox بادوام، ترتیب کپی‌های هم‌زمان و repair هنوز ساخته نشده‌اند. ویرایشگرهای ACF و `review-admin.php` همچنان متای نمایشی را تغییر می‌دهند، نه snapshot رزرو.
- داشبورد موجود هنگام نمایش فرم هنوز می‌تواند از متای نمایشی بخواند و هنگام ذخیره آن را به snapshot منتشر کند؛ فرم کهنه یا ذخیرهٔ هم‌زمان دو تب، بدون expected revision، می‌تواند برنامهٔ جدیدتر را بازنویسی کند. idempotency ذخیرهٔ برنامه و حل پاسخ نامعلوم آن نیز کامل نشده است. این موارد پیش از هر فعال‌سازی واقعی باید حل و آزمایش شوند؛ CI حاضر آنها را اثبات نمی‌کند.
- migration نسخهٔ ۱ اولیه است: import کنترل‌شدهٔ برنامه‌های موجود، هماهنگی migration هم‌زمان، upgrade و rollback عملیاتی و بررسی نصب در محیط مقصد هنوز نیازمند طراحی و آزمون است. هیچ جدول موجود به‌طور خودکار پاک نمی‌شود.
- endpointها، nonce و مدیریت وضعیت/نمایش برای محصول، منشی و مدیر، جریان ورود Google و UI ساخته نشده‌اند. تست nonce رزرو از adapter صرفاً CI است و به معنی وجود endpoint عمومی امن نیست. همهٔ نقش‌ها، انتقال‌های وضعیت، deadlock و سناریوهای ۱۲ بیمار در همین پیاده‌سازی جدید پوشش کامل ندارند؛ بخشی فقط در spike قدیمی آزمایش شده است.
- `wpdb`های drop-in شخص ثالث در حال حاضر fail-closed هستند؛ پشتیبانی آنها اثبات نشده. قطع واقعی **در حین** COMMIT، همهٔ پیکربندی‌های شبکه و object cache و قفل‌ها اثبات نشده‌اند. زمان پاسخ‌ازدست‌رفته در CI بعد از تأیید موفق COMMIT و با بستن واقعی socket کلاینت کنترل شده است.
- مدت پیش‌فرض ۳۰ و بافر پیش‌فرض ۵ دقیقه است؛ ۱۰ دقیقه و تنظیمات دیگر قبل از انتشار نیاز به آزمون دارند. قفل و جزئیات آزموده‌شده جایگزین بازبینی امنیتی و تست‌های production نیستند. هیچ اطلاعات شخصی در گزارش آزمون قرار داده نشده است.
- برای برگشت در شاخه، commit انتقال را می‌توان پس از بررسی وابستگی‌های بعدی revert کرد؛ بستهٔ ۰٫۳٫۱۷ و سایت زنده دست‌نخورده‌اند. rollback سایت یا حذف جدول‌ها در این مرحله انجام نشده و نباید خودکار باشد.

**وضعیت:** در انتظار بازبینی نهایی کارفرما؛ Stage 3، نصب، فعال‌سازی و انتشار تا مجوز جداگانه آغاز نمی‌شوند.
