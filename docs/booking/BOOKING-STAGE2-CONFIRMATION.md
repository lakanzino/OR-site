# تأییدیهٔ نهایی الگوی backend مرحلهٔ دوم

**دروازه مرحله ۲ به طور کامل بسته شد — backend آماده انتقال است**

این عبارت دقیقاً یعنی **الگوی backend در محیط دورریختنی اثبات شده و برای انتقال به فایل‌های واقعی افزونه آماده است**؛ به معنی انجام‌شدن انتقال، قابل نصب‌بودن، تأیید release یا اجرا روی سایت زنده نیست. کارفرما الگو و قرارداد را بازبینی و تأیید کرده است. انتقال و آزمون کد افزونه گام جداگانهٔ بعدی است و Stage 3 محسوب نمی‌شود.

## شواهد

- [CI یکپارچهٔ سبز، اجرای 42137379366](https://github.com/lakanzino/OR-site/actions/runs/42137379366)، commit `7626708`: WordPress 7.1.4، PHP 8.4 و MariaDB 11.4 دورریختنی. `HJ_Doctors_Dashboard::ajax_save` واقعی در کپی افزونه، پس از جایگزینی یک خط ذخیرهٔ ساعات، snapshot را ذخیره کرد. endpoint رزرو آزمایشی با `wpdb`، همان snapshot و همان قفل پزشک را برای خواندن اسلات و ساخت رزرو استفاده کرد؛ متای نمایشی عمداً متفاوت بود.
- هشت بیمار هم‌زمان با بستن ساعات تلاش کردند. هر دو ترتیب قفل با مانع کنترل‌شده آزموده شد: رزرو تأییدشده پیش از بستن باقی می‌ماند؛ درخواست جدید پس از بستن رد می‌شود. شمارش رزروها، جزئیات و کلیدها از تکرار یا گم‌شدن در این سناریو جلوگیری‌شده را بررسی کرد.
- KILL قبل از commit، rollback و retry؛ و پس از commit موفق، KILL اتصال DB و بستن socket کلاینت پیش از پاسخ آزمایش شد. retry همان کلید، حتی به‌صورت هم‌زمان، همان شناسه را برگرداند؛ استفاده از کلید برای درخواست متفاوت یا بیمار دیگر رد شد. timeout واقعی قفل با retry محدود و همچنین تأیید/لغو/رزرو مجدد در مسیر آزمایشی بررسی شد.
- [CI ضدنمونهٔ 42134620828](https://github.com/lakanzino/OR-site/actions/runs/42134620828) خطر reconnect خودکار `wpdb` stock را بازتولید کرد؛ سبز بودن آن نشانهٔ کشف خطر است، نه رفع عمومی آن. [قرارداد ادغام](BOOKING-STAGE2-INTEGRATION-CONTRACT.md) و [گزارش آزمون](BOOKING-STAGE2-TEST-REPORT.md) جزئیات و موارد باز را دارند.

## محدودیت‌ها و کار ادغام

- `hj_ci_booking_operation` و subclass بدون reconnect فقط fixture هستند؛ `hj_secured_create` و سایر APIهای production هنوز به snapshot متصل نشده‌اند. سازگاری با drop-inهای پایگاه داده، قطع حین COMMIT و همهٔ خطاها/نقش‌ها در محیط واقعی اثبات نشده است. زمان تزریقی و تاریخ ثابت فقط برای آزمون هستند.
- برخی آزمون‌های ۱۲ بیمار، نقش منشی/مدیر و انتقال وضعیت همچنان در نمونه‌های جداگانه و عمدتاً با mysqli اجرا شده‌اند؛ نباید آنها را آزمون همین endpoint یکپارچه تلقی کرد. آزمون deadlock و همهٔ مسیرهای status روی این endpoint کامل نیست.
- شکست کپی نمایشی با skip شبیه‌سازی شده است، نه با `update_field` ناموفق یا ACF Pro واقعی. بنا به تصمیم معماری، ACF مرجع اعتبار رزرو نیست؛ نمایش ممکن است کهنه بماند و outbox/repair و ترتیب کپی‌ها برای ادغام لازم است.
- همهٔ writerهای مؤثر بر ظرفیت، migration نسخه‌دار، idempotency ذخیرهٔ برنامه، اعتبارسنجی سخت، timeout/retry مسیرهای دیگر و پیام نتیجهٔ نامعلوم باید پیش از انتشار تولیدی تکمیل و دوباره بررسی شوند. مدت پیش‌فرض ۳۰ دقیقه و بافر آزمون یکپارچه ۵ دقیقه است؛ گزینهٔ بافر ۱۰ دقیقه و قابلیت توسعهٔ تنظیمات باید در ادغام نهایی لحاظ و آزموده شوند.
- در زمان اجرای CI فوق افزونهٔ اصلی، سایت زنده، UI و shortcode تغییر نکرده بودند. انتقال الگو فقط روی شاخهٔ کاری انجام می‌شود؛ تا CI سبز روی فایل‌های واقعی افزونه نباید ادعای ادغام تکمیل‌شده کرد. سایت زنده دست‌نخورده می‌ماند و مرحلهٔ ۳ تا اجازهٔ جداگانهٔ کارفرما شروع نمی‌شود.
