# مرحلهٔ ۵.۳۳ — تکرار کنترل‌شدهٔ race با workerهای مستقل

پس از جداسازی مرحلهٔ ۵.۳۲، هر دو آزمون ساخت اولیه سه مرتبه و هر مرتبه برای یک کاربر ساختگی تازه انجام می‌شوند: ضدنمونهٔ محصول بدون claim و نمونهٔ آزمایشی claim. هر دو درخواست هر نوبت باید پیش از آزادشدن به barrier برسند و PIDهای marker باید دقیقاً با دو worker مستقل مطابقت کنند. نتیجهٔ پست و snapshot هر نوبت بررسی می‌شود؛ این جایگزین داده یا نصب واقعی نیست.

Markerهای barrier اکنون ابتدا در فایل موقت و سپس با rename روی همان filesystem منتشر می‌شوند تا مشاهدهٔ فایل خالی بین ایجاد و نوشتن داده باعث خوانش ناقص PID نشود؛ این، شرط‌های آزمون را ضعیف نمی‌کند. [PHP manual](https://www.php.net/manual/en/features.commandline.webserver.php) به محدودیت هم‌زمانی سرور توسعه اشاره دارد. کد محصول تغییری نکرده است.

**در انتظار CI:** سه تکرار محدود نشانه‌ای دربارهٔ این fixture خواهند بود، نه اثبات ریشهٔ خطاهای قبلی یا صحت همهٔ زمان‌بندی‌ها. سه بدهی فرم، ایجاد تکراری، بازیابی و migration باز، **۷۵٪ ثابت و NO-GO**.
