# 02 — ترتیب نصب

======================================================================



## گام ۰ — قبل از هر کاری

1. یک **بکاپ کامل** (فایل + دیتابیس) با UpdraftPlus/Backuply بگیر و فایل را روی یک مقصد بیرون از سرور نگه دار.

2. اگر محیط staging داری، اول آنجا نصب کن.

3. ACF Pro فعال باشد. Nextend Social Login نصب باشد.

4. موقتاً در wp-config.php (نمایش خطا خاموش، لاگ روشن):

   ```php

   define('WP_DEBUG', true);

   define('WP_DEBUG_LOG', true);

   define('WP_DEBUG_DISPLAY', false);

   ```

   (پایان کار برگردان.)

5. وردپرس را با مدیر کل باز نگه دار، و یک پنجرهٔ ناشناس (Incognito) هم برای تست مهمان.



## گام ۱ — کپی افزونه

1. پوشهٔ `hamyar-doctors/` را با ساختار فصل ۰۱ بساز (FTP یا File Manager).

2. همهٔ فایل‌های includes/، assets/css، assets/js، assets/fonts/fonts.css، acf-json/ را بگذار.

3. فونت‌ها: `Vazirmatn[wght].woff2` از GitHub rastikerdar/vazirmatn (Releases) → تغییر نام به `Vazirmatn-Variable.woff2`؛ `InterVariable.woff2` از rsms.me/inter → تغییر نام به `Inter-Variable.woff2`. هر دو را در assets/fonts/ بگذار. (منبع‌ها از حافظه است؛ اگر لینک تغییر کرده بود، همین فونت‌ها را از منبع رسمی دیگر بگیر.)

4. عکس اتاق عمل (JPG حدود ۸۰۰×۸۰۰ تا ۱۲۰۰×۹۰۰، زیر ~۱۵۰KB، بدون چهره و متن) را در assets/img/operating-room.jpg بگذار. (اگر الان نداری، بعداً از ابزار بخش ۱۴ هم می‌شود آپلود کرد.)

5. در پیشخوان → افزونه‌ها → «Hamyar Doctors» را **فعال کن**.

6. ✋ **توقف‌گاه:** سایت باید لود شود و پیشخوان باز بماند. اگر صفحهٔ سفید/۵۰۰ شد: در wp-config.php `define('HJ_DOCTORS_SAFE_MODE', true);` یا نام پوشهٔ افزونه را عوض کن و لاگ را بفرست.



## گام ۲ — ذخیرهٔ پرمالینک

پیشخوان → تنظیمات → پیوندهای یکتا → فقط «ذخیره» بزن (برای ثبت /province/ ، /city/ ، /specialty-type/).

تست: /doctor/ و /specialty/orthopedics/ هنوز باز شوند.



## گام ۳ — فیلدهای ACF

1. ACF → Field Groups: اگر دو گروه «Doctor Profile» و «Doctor System» دیده نشد یا «Sync available» داشت، Sync کن.

2. اگر باز دیده نشد (مسیر load_json بخش ۳ کار نکرد): ACF → Tools → Import Field Groups و دو فایل JSON را import کن.

3. تست: یک پزشک نمونه را در پیشخوان باز کن؛ فیلدها (name_fa، name_en، working_hours و …) باید دیده شوند. دوتا گروه تکراری نساز.



## گام ۴ — قالب فرزند (دقت بالا؛ اینجا خطا = صفحهٔ سفید)

1. از `lax-theme-child/functions.php` یک کپی بکاپ بگیر (در پوشهٔ خودت، نه روی سایت).

2. اگر فایل آخرش `?>` دارد، آن را بردار.

3. به‌ترتیب **در انتهای** فایل append کن: (الف) قطعهٔ بخش ۱ (body class)، (ب) کلاس HJ_Theme_Layer (بخش ۱۳). چیزی از قبلی را حذف نکن.

4. با FTP/File Manager ذخیره کن (نه با ویرایشگر قالب پیشخوان).

5. **بلافاصله** یک صفحهٔ سایت را باز کن. اگر خطا بود: فایل بکاپ را برگردان.

6. قالب‌ها را بگذار: single-doctor.php, archive-doctor.php, taxonomy-specialty.php, taxonomy-province.php, taxonomy-city.php, taxonomy-specialty_type.php.

7. تست: /doctor/dr-demo-general/ و /doctor/ باز شوند.



## گام ۵ — دادهٔ اولیه (بخش ۱۴)

پیشخوان → ابزارها → «ورود داده‌ها (همیار)»

1. **تخصص‌ها:** دکمهٔ «ساخت تخصص‌های ناموجود». انتظار: ساخته‌شده ۰، موجود ۱۱ (چون از قبل هست).

2. **آزمون کوچک:** فایل test.csv (UTF-8):

   ```

   province,province_slug,province_en,city,city_slug,city_en

   تهران,tehran,Tehran,ری,ray,Rey

   البرز,alborz,Alborz,کرج,karaj,Karaj

   ```

   اول با تیک «فقط پیش‌نمایش»، بعد بدون تیک، بعد یک‌بار دیگر (باید همه «بدون تغییر» باشد).

3. **فایل اصلی sarzaminaryan** (از کاربر بگیر؛ فصل ۰۷): ابتدا پیش‌نمایش؛ باید «۳۱ استان ✓ و ۴۸۳ شهرستان ✓» بیاید؛ سپس اجرای واقعی.

4. صفحهٔ hj_seed_status: جمع شهرستان‌ها = ۴۸۳؛ «شهرستان بدون استان» = ۰.

5. عکس پیش‌فرض: اگر فایل assets نگذاشتی، همین‌جا آپلود کن.



## گام ۶ — ورود با گوگل

مطابق فصل ۰۶. بعد از آن hj_auth_status.



## گام ۷ — صفحه‌ها و منو

- صفحهٔ /my-profile/ باید منتشر شده باشد. اگر مهمان کارت ورود را نمی‌بیند، شورت‌کد `[hj_doctor_dashboard]` را در محتوای صفحه بگذار.

- (اختیاری) دکمهٔ ورود پزشکان در جایی از سایت: `[hj_google_login]`.

- جست‌وجوی پزشک: شورت‌کد `[hj_doctor_search]` یا ویجت «HJ Doctor Search»؛ یا ثابت HJ_HEADER_SEARCH_MENU (بخش ۱۰) اگر می‌خواهی در منوی هدر بنشیند. هدر `lax-theme` را دستکاری نکن.



## گام ۸ — امتیازدهی

1. hj_rb_status را باز کن: جدول `hj_doctor_votes` و ستون‌ها باید شناخته شوند (نام جدول با پیشوند وردپرس).

2. **ریسک شناخته‌شده:** رابط قدیمی امتیاز در پروفایل جدید دیده نمی‌شود تا به قلاب `hj_doctor_rating_box` وصل شود. وضعیت را در hj_pr_status ببین و گزارش بده.

3. رأی‌های جدید همیشه «در انتظار» ثبت می‌شوند و تأیید دستی در داشبورد قدیمی «آرای پزشکان» انجام می‌شود (دست‌نخورده).

4. کش REST/ویجت بعد از تأیید رأی در داشبورد قدیمی تا ۹۰۰ ثانیه عقب می‌ماند؛ دکمهٔ «پاک‌سازی کش» در hj_rest_status را بزن.



## گام ۹ — بررسی همهٔ صفحه‌های وضعیت (به‌ترتیب)

hj_auth_status → hj_dash_status → hj_pr_status → hj_ar_status → hj_rb_status → hj_sf_status →

hj_rest_status → hj_wd_status → hj_theme_status → hj_seed_status → hj_hooks_status

برای هر صفحه یک اسکرین‌شات یا متن کپی برای کاربر ذخیره کن.



## گام ۱۰ — فونت و تم

فصل ۰۹. دارک‌مود **خاموش بماند** مگر پس از تست با `?hj_theme=dark`.



## گام ۱۱ — Nginx، کش، بکاپ

فصل‌های ۰۴ و ۰۵. **قبل از جمع‌آوری مدارک واقعی** قانون Nginx تأیید شود.



## گام ۱۲ — پایان

- WP_DEBUG را به حالت قبل برگردان.

- چک‌لیست فصل ۰۳ را کامل اجرا کن.

- یک بکاپ نهایی بگیر و نام آن را با تاریخ در Drive ثبت کن.
