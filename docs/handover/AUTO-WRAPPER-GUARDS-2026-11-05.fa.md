# گارد سخت‌گیرانهٔ wrapper و آزمون‌های دورریختنی — ۵ نوامبر ۲۰۲۶

## توافق و تغییر

مشاور از طریق کارفرما قرارداد `HJ_ALLOW_AUTO_SEED === true`، گارد فقط روی سه wrapper خودکار و حفظ گزارش دودویی option را پیشنهاد و ترتیب آزمون‌ها را تأیید کرد. در افزونهٔ درحال‌توسعهٔ ۰٫۳٫۱۱ ابتدای `hj_iran_locations_auto_seed`، `hj_iran_locations_auto_repair` و `hj_demo_doctors_auto_seed` محافظ سخت‌گیرانه اضافه شد. ثابت تعریف‌نشده، `false` و رشتهٔ `'true'` اجازهٔ اجرای wrapper نمی‌دهند؛ مقدار بولی `true` فقط اجازهٔ عبور از گارد و ادامهٔ بررسی‌های قبلی مانند نقش و marker را می‌دهد. هیچ hook خودکار ثبت نشده است؛ صرف تعریف ثابت و بازکردن پیشخوان حتی با `true` هیچ wrapperی را صدا نمی‌زند. فراخوانی مستقیم توابع اصلی یا مسیرهای دیگر تحت پوشش این گارد نیست؛ کد بیرونی ممکن است به رفتار سابق wrapper وابسته باشد.

توابع اصلی seed/repair/delete و محتوای گزارش option تغییر نکردند. تنها تغییر اضافی لازم برای انطباق تست نقش، پاسخ handler دستی دمو برای کاربر فاقد `manage_options` است: `wp_die` اکنون صریحاً HTTP 403 می‌دهد. در اجرای نخست تست، درخواست subscriber با nonce معتبر واقعاً رد شد، اما HTTP آن 500 بود؛ پس از اصلاح 403 و تست مجدد موفق شد. تغییری در سطح دسترسی یا nonce داده نشد.

## نتایج آزمون

- شبیه‌ساز PHP 8.3 WASM با توابع اصلی mockشده: فراخوانی مستقیم هر سه wrapper برای ثابت تعریف‌نشده، false بولی و رشتهٔ `'true'` بدون رسیدن به تابع اصلی یا transient؛ برای true بولی هر سه به تابع اصلی رسیدند. کنترل پیشین capability و marker در true نیز مانع اجرا شد. تست جداگانهٔ ثبت hook و parser هم موفق است. ابزارها: `tools/hamyar-php-review/run-seed-wrapper-guard-test.mjs` و `run-seed-hook-test.mjs`.
- WordPress 6.8.3/PHP 8.3/SQLite در Playground با DB دورریختنی: چهار درخواست تست با فراخوانی مستقیم هر سه wrapper. در سه حالت اول snapshot شمار پست‌ها، چهار taxonomy و سه option تغییر نکرد؛ در حالت true با پیش‌شرط‌های لازم، seed مکان، repair و seed دمو اجرا شدند و سه option ثبت و پنج پست نمونه ایجاد شد. این آزمون تمام جدول‌ها و hookهای محیط واقعی را بررسی نمی‌کند.
- نصب دورریختنی دوم با ثابت بولی true در تمام درخواست‌ها: ورود مدیر و بارگذاری واقعی wp-admin هیچ دمو یا option سه‌گانه نساخت و سه hook همچنان غایب بودند. بنابراین سناریوی پیشنهادی «true + admin_init لزوماً اجرا شود» با تصمیم قبلی حذف hook سازگار نیست و بازاتصال داده نشد.
- HTTP واقعی به handler دمو: مدیر با nonce معتبر seed زد، ریدایرکت 302 به ابزار و GET 200 دریافت شد، پنج پزشک نشان‌دار ساخته شدند؛ حذف دستی، 302 و GET 200 و سپس بارگذاری مجدد پیشخوان، صفر پست و option دمو غایب و بدون بازسازی را نشان داد. مدیر با nonce نامعتبر 403 و subscriber با nonce معتبر پس از اصلاح 403 گرفت. هر گونه ساخت/حذف فقط روی DB دورریختنی بوده است؛ این تست پاک‌شدن همهٔ رأی‌ها یا ترم‌های وابسته را ادعا نمی‌کند.
- فرم‌های دستی مکان و repair در همان DB دورریختنی با nonce معتبر مدیر، پاسخ HTTP 200 و notice موفقیت داشتند؛ این دو مسیر در صفحه اجرا می‌شوند و redirect ندارند. صحت همهٔ جزئیات مجموعهٔ taxonomy یا رفتار nonce نامعتبر آنها در این نوبت به‌طور جامع آزموده نشده است.
- بستهٔ آزمایشی `releases/hamyar-doctors-0.3.11.zip` از سورس جدید و بدون tests بازسازی و با header/ثابت/تمام سورس بسته تطبیق داده شد. SHA256: `16749cd7b37ae508da7eec94f160dbf3193e885d49dc103acec0959288247d0e`. ۹ تست نسخه قالب، `git diff --check` و parser هم موفق بودند. قالب در این گام تغییر نکرد.

## محدودیت و وضعیت انتشار

این آزمون‌ها MySQL، دادهٔ سایت واقعی، فیلترهای بیرونی، تداخل کد بیرونی، حجم بالا و rollback DB را پوشش نمی‌دهند. تست HTTP موقتی فقط روی Playground و محیط غیرزنده اجرا شد و دو سرور متوقف شدند. گاردها ناسازگاری احتمالی با مصرف‌کنندگان مستقیم قبلی wrapper ایجاد می‌کنند؛ بازگشت به افزونهٔ قدیمی ممکن است hookهای قدیمی را بازگرداند و rollback فایل جایگزین بازیابی DB نیست.

در زمان نگارش، ادغام/ریلیز/نصب این تغییر انجام نشده؛ وضعیت نهایی در PR و دفتر همکاری ثبت می‌شود. نصب زنده تنها توسط کارفرما، پس از تصمیم مستقل، بکاپ فایل و DB قابل‌بازیابی و ثبت صفحهٔ نخست است. مدیریت رأی و تغییر ناوبر هنوز ساخته نشده‌اند.
