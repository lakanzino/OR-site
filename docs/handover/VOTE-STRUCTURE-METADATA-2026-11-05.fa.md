# پیشرفت شناخت ساختار رأی — نسخهٔ کاری ۰٫۳٫۱۳

## هدف و محدوده

پس از دریافت گزارش مدیر و رفع ابهام تفاوت آمار پروفایل توسط کارفرما، مرحلهٔ شناخت ساختار رأی ادامه یافت. در گزارش مستقلِ تنها مخصوص مدیر با `manage_options`، سه ردیف metadata اضافه شده است:

1. آیا جدول شناسایی‌شدهٔ پل هم‌نام جدول پیش‌فرض استفاده‌شده برای نظرات پروفایل است؛ این به معنی یکسانی فیلترها یا نتایج آنها نیست.
2. آیا ستون شناسه‌ای که پل شناسایی کرده **به‌تنهایی** کلید اصلی است. خروجی `بله`، `خیر یا کلید مرکب` یا `نامعلوم` است؛ ستون دیگر می‌تواند کلید یکتای غیر اصلی داشته باشد و پاسخ منفی به معنی نبود هرگونه یکتایی نیست.
3. گروه کلی نوع ستون status: عددی/بولی، متنی/فهرستی، نوع دیگر یا نامعلوم. گروه نوع نشان‌دهندهٔ معنی status یا شمار رأی‌ها نیست.

فقط `SHOW COLUMNS` روی جدول شناسایی‌شده، پس از بررسی سخت‌گیرانهٔ نام مجاز `[A-Za-z0-9_]` اجرا می‌شود. هیچ ردیف رأی، متن، شناسه شخص یا نام واقعی جدول و ستون در این بخش خوانده یا نمایش داده نمی‌شود. نتیجه خالی، ناقص، خطا یا استثنا به‌عنوان نامعلوم گزارش می‌شود. وضعیت موقت سرکوب خطای `$wpdb` پس از همین کوئری با `finally` به حالت قبل بازمی‌گردد. فیلترها و hookهای سایر اجزای وردپرس و رفتار موجود `schema()` خارج از تضمین این تابع هستند.

این نسخهٔ کاری جایگزین ابزار مدیریت، تأیید، ویرایش یا حذف رأی، شمارش وضعیت‌ها یا احراز صلاحیت نیست؛ سیاست نمایش عمومی را نیز تغییر نمی‌دهد. جدول سازنده و معنی status واقعی از مخزن به‌تنهایی مشخص نیست. ZIP صرفاً آزمایشی و بدون tests است؛ انتشار و نصب زنده در این مرحله انجام نشده است. قالب و داده‌های سایت تغییر نکردند.

## آزمون‌ها

- PHP 8.3 WASM با `$wpdb` شبیه‌سازی‌شده: کلید اصلی تکی/مرکب/نبود کلید، type متن/عدد/دیگر، جدول یکسان/متفاوت، داده ناقص، خطا و استثنا، بازگشت suppression، رد نام جدول نامعتبر قبل از کوئری و رد mapping نامعتبر. این آزمون DB واقعی نیست.
- WordPress 6.8.3/PHP 8.3 و WordPress 7.1.4/PHP 8.4 در Playground/SQLite دورریختنی: جدول غایب، جدول مصنوعی با PK تکی و بدون/با status، متن گزارش، عدم نمایش شناسه نمونه و ثابت ماندن رأی مصنوعی پس از نمایش. آزمون دسترسی anonymous/subscriber/doctor، POST، escaping، عدم فرم، گزارش خطای DB، hook priority-zero و state منتخب روی WordPress 6.8.3 موفق بود. اتصال واقعی HTTP، داده انبوه و تمام اثر hookها آزموده نشده‌اند.
- یک workflow مستقل GitHub با MariaDB 11.4 دورریختنی، WordPress 7.1.4 و PHP 8.4 و دیتابیس خالی ساخته شد. اجرای نخست روی commit `b970bd3` برای گزارش دسترسی/خطا و جدول مصنوعی رأی با کلید اصلی تکی و status متنی موفق شد؛ این محیط سایت زنده یا نسخه دقیق patch آن نیست. سناریوهای مرکب و عددی بعداً به تست اضافه شدند؛ وضعیت اجرای commit بعدی باید جداگانه بررسی شود.
- تطبیق ZIP افزونه با سورس و نسخه و نبود tests، parser PHP، تست قلاب و ۹ تست هماهنگی قالب موفق شدند. SHA256 ZIP آزمایشی `8e899b9cf40c9a762e2ace4ab9642e6890a55335473fefbe3159130c24c4a05f`.
- ترکیبات واقعی schema و فیلترهای سایت، داده انبوه و سیاست تأیید واقعی هنوز آزموده نشده‌اند. پیش از انتشار و درخواست نصب، بررسی Sonnet، نتایج نهایی CI و بازبینی عوارض ارتقا لازم است. هیچ نصب یا تغییر داده زنده توسط ایجنت مجاز نشده است.
