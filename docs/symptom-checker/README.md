# چک‌کنندهٔ علائم: راهنمای نگهداری و افزودن بیماری

وضعیت: **آزمایشی و بدون بازبینی پزشکی**. همهٔ ۱۲۰ پروفایل `review.status = "draft"` هستند و در فضای تست نمایش داده می‌شوند با برچسب «پیش‌نویس». این ابزار تشخیص نمی‌دهد.

## منبع حقیقت: `src/`

داده‌ای که باید ویرایش شود در `themes/lax-theme-child/data/symptom-checker/src/` است:

| فایل | نقش |
|---|---|
| `src/diseases/<id>.json` | یک پروفایل بیماری: نام، سن و جنسیت، برچسب‌ها با `freq` و `role` (core / supporting)، علائم، موارد مراجعهٔ فوری، منابع، وضعیت بازبینی |
| `src/tags.json` | ۶۰ برچسب علامت: برچسب فارسی، پرسش بله/خیر، تعریف، ناحیه (`category`) |
| `src/red-flags.json` | ۱۶ قاعدهٔ خطر فوری با شرط `all` / `any` روی برچسب‌ها و پیام اورژانس |

خروجی‌ها تولیدی‌اند و نباید دستی ویرایش شوند:

| فایل | نقش |
|---|---|
| `diseases.json` | داده‌ی موتور (`rankable`، `tagRoles`، `ageGroups`، `sex`، `reviewStatus`) |
| `vocab.json` | ناحیه‌ها، سن‌ها، برچسب‌ها، پرسش‌های خطر فوری |

ابزارها:
| ابزار | کار |
|---|---|
| `tools/migrate-seed.py` | تبدیل اولیهٔ داده‌ی قدیمی به `src/`. **دوباره اجرا نکنید** مگر با حذف دستی `src/`. |
| `tools/build-symptom-db.py` | ساخت `diseases.json` و `vocab.json` از `src/`. `--published-only` فقط پروفایل‌های منتشرشده را می‌سازد. |
| `tools/validate-symptom-db.py` | اعتبارسنجی. `--strict` هشدارهای داده‌ی ناقص را خطا می‌کند (دروازهٔ انتشار). |

## قواعد موتور (خلاصه)
- سن و جنسیت فیلترند، شاهد نیستند. بیماری‌ای که با سن یا جنسیت نمی‌خواند حذف می‌شود.
- همهٔ پرسش‌های خطر فوری اول پرسیده می‌شوند. «بله» یعنی نتیجهٔ اورژانس و بدون رتبه‌بندی. «نمی‌دانم» فقط هشدار احتیاط می‌دهد.
- برچسب‌های ناحیهٔ انتخاب‌شده (حداکثر ۴ مورد پرتکرار) اول پرسیده می‌شوند، بعد پرسش‌هایی که بیشترین تفکیک را دارند.
- امتیاز = (وزن برچسب‌های تأییدشده − جریمهٔ برچسب core ردشده) ÷ کل وزن. core وزن ۲ و supporting وزن ۱ دارد. حداقل ۲ برچسب تأییدشده لازم است.
- بیماری با کمتر از ۳ برچسب `rankable=false` است و رتبه نمی‌گیرد. اگر هیچ بیماری قابل رتبه‌بندی نماند، نتیجه «اطلاعات کافی نیست» است.
- نتیجه یک سطح همخوانی نسبی است (بالا / نسبی / ضعیف)، نه احتمال عددی.
- حداکثر ۱۵ پرسش. توقف وقتی یک گزینه روشن پیشتاز است.

## افزودن یا اصلاح یک بیماری
1. فایل `src/diseases/<id>.json` را بسازید یا ویرایش کنید. برچسب‌ها فقط از `tags.json` باشند.
2. اگر برچسب تازه لازم است، ابتدا آن را در `tags.json` با تعریف و پرسش بنویسید.
3. اجرا کنید:
   ```bash
   python3 tools/build-symptom-db.py
   python3 tools/validate-symptom-db.py          # خطاها را رفع کنید
   python3 tools/validate-symptom-db.py --strict # قبل از انتشار: هشدارها هم صفر شوند
   cd themes/lax-theme-child && node --test tests/symptom-checker-engine.test.js
   cd themes/lax-theme-child && node --test tests/clinical-scenarios.test.js
   ```
4. برای انتشار، `review.status` را به `published` با نام و تاریخ بازبینی تغییر دهید و `--published-only` بسازید.

## شناختهٔ‌شده: داده‌ی ناقص
- ۵۴ بیماری کمتر از ۳ برچسب دارند و رتبه نمی‌گیرند. فهرست در `reports/needs-review.md` است.
- برچسب‌های core از ترتیب برچسب‌های مهاجرت آمده‌اند، نه از تشخیص پزشکی. بازبینی پزشکی باید آن‌ها را اصلاح کند.
- فرکانس‌ها پیش‌فرض `common` هستند. منابع فقط نام‌اند و URL ندارند.
- درمان خانگی در خروجی نیست. اعتبارسنجی آن را با کلمات کلیدی بررسی می‌کند.

## تست‌ها
- `tests/symptom-checker-engine.test.js`: ۱۴ آزمون موتور (فیلتر سن و جنسیت، خطر فوری، داده‌ی ناکافی، ساختار نتیجه).
- `tests/clinical-scenarios.test.js` و `clinical-scenarios.json`: ۵ ویزیت شبیه‌سازی‌شده. این مجموعه کامل نیست و برای ادعای دقت کافی نیست.
- هنوز تست مرورگر (Playwright) و تست PHP وجود ندارد.
