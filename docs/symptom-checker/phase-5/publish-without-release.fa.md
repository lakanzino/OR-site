# فاز ۵-الف — انتشار محتوا بدون انتشار افزونه

**تاریخ:** ۳۱ اکتبر ۲۰۲۶ · **افزونه:** `0.1.8` · **فایل:** `releases/hamyar-symptom-checker-0.1.8.zip`

---

## ۱. مسئله

بستهٔ دانش داخل زیپ افزونه بود (`assets/data/knowledge-bundle.v1.json`). نتیجه: **هر بیماری تازه یا هر اصلاح متن = افزونهٔ تازه**. برای ابزاری که کل ارزشش «بیماری تازه با داده» است، این یعنی هر محتوای تازه یک ریسک نصب دارد.

## ۲. راه‌حل

| جزء | کار |
| --- | --- |
| CLI | `author.py publish-bundle` فایل را با نام `knowledge-bundle.<bundle_version>.<sha8>.json` می‌نویسد |
| افزونه | همان فایل را از `wp-content/uploads/hj-sc/` می‌خواند؛ اگر نبود یا نامعتبر بود، بستهٔ داخل زیپ |
| انتخاب نسخه | option `hj_sc_active_bundle` نام فایل فعال را نگه می‌دارد؛ خالی باشد → تازه‌ترین بستهٔ معتبر |
| کش | نشانی بستهٔ آپلودی `?ver=<sha8>` دارد؛ نسخهٔ قدیمی از کش LiteSpeed/مرورگر سرو نمی‌شود |
| بازگشت | یک option؛ یا پاک‌کردن فایل (بازگشت خودکار به زیپ) |

**ترتیب تصمیم (کد، `includes/bundle-source.php`):**

```text
option hj_sc_active_bundle  →  اگر فایلش معتبر بود: همین
        ↓ نبود
تازه‌ترین knowledge-bundle.*.json معتبر در uploads/hj-sc/   (با فیلتر hjsc_bundle_autodetect قابل خاموش‌کردن)
        ↓ نبود
assets/data/knowledge-bundle.v1.json داخل زیپ                (همیشه، هرگز صفحهٔ خالی)
```

**«معتبر» یعنی:** نام با الگوی `^knowledge-bundle\.[0-9A-Za-z._-]+\.[0-9a-f]{8}\.json$` بخواند، فایل خواندنی باشد، JSON سالم باشد، `schema_version` یکی از `1.0.0`/`2.0.0` باشد و `questions` خالی نباشد. **اعتبارسنجی محتوا کار CLI است، نه افزونه** — افزونه فقط «شکل» را می‌سنجد.

## ۳. دستورهای واقعی

```sh
A=tools/symptom-checker-author/author.py

# ساخت فایل انتشار (نسخهٔ minor خودکار بالا می‌رود اگر محتوا عوض شده باشد)
python3 $A publish-bundle                       # → dist/hj-sc/knowledge-bundle.<version>.<sha8>.json
python3 $A publish-bundle --check               # اگر فایل کهنه باشد، کد خروج ۱

# روی سرور
mkdir -p wp-content/uploads/hj-sc
# فایل را با SFTP/FTP/فایل‌منیجر هاست در همان پوشه بگذارید
```

برای **قفل‌کردن** یک نسخهٔ خاص (مثلاً برگشت):

```php
update_option( 'hj_sc_active_bundle', 'knowledge-bundle.0.2.0-draft.bf0eb60e.json' );
```

و برای برگشت به «همیشه داخل زیپ»:

```php
delete_option( 'hj_sc_active_bundle' );
# یا اگر می‌خواهید حتی فایل‌های موجود هم نادیده گرفته شوند:
add_filter( 'hjsc_bundle_autodetect', '__return_false' );
```

## ۴. چه چیزی **اضافه نشد** (عمدی)

- هیچ endpoint تازه، هیچ AJAX تازه، هیچ `admin_post`.
- هیچ ذخیره‌سازی پاسخ؛ هیچ درخواست بیرونی؛ فایل فقط محلی خوانده می‌شود.
- هیچ پست‌تایپ یا ویرایشگر محتوا در پیشخوان (آن فاز ۵-ب است و تصمیم جداست).
- هیچ اعتبارسنج بالینی در افزونه؛ فقط بررسی شکل.

## ۵. آزمون‌ها

| آزمون | نتیجه |
| --- | --- |
| PHP (WASM، روی بستهٔ ساخته‌شده) | **۲۴/۲۴ سناریو، ۱۳۷ بررسی** — ۸ سناریوی تازه: بستهٔ زیپ، بستهٔ آپلودی، قفل نسخهٔ قدیمی، قفل به فایل گم‌شده، انتخاب «تازه‌ترین» با `version_compare`، فایل خراب/اسکیمای غلط/بی‌پرسش/نام نامعتبر، خاموش‌کردن autodetect، تلاش `../` و نام‌های نامعتبر |
| WordPress واقعی (Playground ۶.۸.۳) | بستهٔ آپلودی فعال می‌شود، `?ver=` درست است، فایل با ۲۰۰ و `schema_version 2.0.0` و ۱۷ پرسش سرو می‌شود، رابط با همان بسته بالا می‌آید، و با حذف فایل **خودکار** به بستهٔ زیپ برمی‌گردد |
| CLI | `publish-bundle` (+`--check`)، نام‌گذاری و هش، رد کردن دادهٔ خراب: در ۲۱ آزمون ابزار نویسندگی |
| بسته | ۲۳ فایل؛ `build_package --check` سبز؛ محرمانگی پاک؛ هم‌نامی: هیچ |

## ۶. ریسک‌ها و مهارشان

| ریسک | مهار |
| --- | --- |
| آپلود فایل خراب → صفحهٔ خالی | چهار لایهٔ اعتبارسنجی + بازگشت خودکار به زیپ |
| کش، نسخهٔ قدیمی را نگه دارد | `?ver=<sha8>` در نشانی بستهٔ آپلودی |
| فایل درست در مسیر اشتباه | PHP فقط `uploads/hj-sc/` را می‌بیند؛ `..` و مسیر مطلق رد می‌شوند |
| نسخهٔ نامعلوم روی سایت | `config.bundleStatus` (source/name/sha8/schema/version) در کد صفحه؛ از کنسول مرورگر دیده می‌شود |
| پوشهٔ uploads غیرقابل‌نوشتن | افزونه به زیپ برمی‌گردد؛ صفحه سالم می‌ماند |

## ۷. چه چیزی اثبات نشده

- روی سایت زندهٔ صاحب سایت اجرا نشده؛ فقط در Playground ۶.۸.۳ (و در CI: ۶.۸.۳ و ۷.۱.۴).
- کش LiteSpeed در محیط واقعی آزموده نشده؛ فقط وجود `?ver=` تضمین شده است.
- اگر هاست `uploads` را از اجرای PHP جدا کرده باشد (که در وردپرس معمول نیست)، فایل خوانده نمی‌شود و همان fallback فعال می‌شود.
