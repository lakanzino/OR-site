## چرا نسخهٔ ۰.۱.۱ روی سایت فعال نشد

پیام «این افزونه به دلیل داشتن مشکل جدی، فعال نشد» یعنی درست در همان درخواست فعال‌سازی، یک خطای مرگبار PHP رخ داده است. پیام خودش علت را نمی‌گوید و سایت هم `WP_DEBUG` را روشن ندارد. رایج‌ترین علت‌ها روی هاست واقعی:

1. ساخت برگه **در همان درخواست فعال‌سازی** (محدودیت حافظه، تایم‌اوت، افزونهٔ امنیتی که `wp_insert_post` را می‌بندد).
2. ZIP که کامل باز نشده و یکی از فایل‌های `includes/` روی سرور نیست.
3. تفاوت نسخهٔ PHP/وردپرس با محیط آزمون و یکی از توابع کمکی.

**بعد از دیدن گزارش سلامت سایت:** نسخه‌ها مانع نیستند — WordPress **7.1.4** و PHP **8.4.27**، یعنی بالاتر از حداقل‌های هدر افزونه، و همان هستهٔ ۷.۱.۴ در آزمون محلی ۳۶/۳۶ پاس می‌شود. پس علت را باید در همان درخواست فعال‌سازی یا در ناقص باز شدن ZIP جست، نه در نسخه‌ها. جزئیات: [گزارش محیط سایت](../../reports/site-health-2026-10-31.fa.md).

۰.۱.۲ هر سه را هدف گرفته است: فعال‌سازی دیگر هیچ برگه‌ای نمی‌سازد، فایل‌ها با نگهبان بارگذاری می‌شوند و هر خطایی به یک پیام خوانا تبدیل می‌شود.

## نصب

1. **پشتیبان** فایل‌ها و پایگاه داده.
2. «پیشخوان ← افزونه‌ها ← افزودن ← بارگذاری افزونه» و انتخاب `hamyar-symptom-checker-0.1.2.zip`.
3. جایگزینی نسخهٔ ۰.۱.۱ (یا ۰.۱.۰) را تأیید کنید، سپس **فعال کنید**.
4. یک بار دیگر پیشخوان را باز کنید (یا صفحهٔ افزونه‌ها را نوسازی کنید)؛ برگهٔ **پیش‌نویس** `symptom-checker` در همین بازدید ساخته می‌شود.
5. اگر کش صفحه فعال است (LiteSpeed Cache)، یک‌بار «پاک‌کردن همهٔ کش» را بزنید.

**راه برگشت:** غیرفعال‌کردن افزونه کافی است؛ هیچ برگه/نوشته/متایی حذف نمی‌شود. برای برگشت به نسخهٔ قبل، همان ZIP قدیمی را دوباره بارگذاری کنید.

## اگر وردپرس اجازهٔ نصب نداد

این‌ها خطاهای **بارگذاری** هستند، نه فعال‌سازی — و هیچ‌کدام به بستهٔ ZIP مربوط نیست:

| پیام وردپرس | معنا | کار |
|---|---|---|
| «نصب با شکست روبه‌رو شد: پوشهٔ مقصد از قبل وجود دارد.» (Destination folder already exists) | پوشهٔ `wp-content/plugins/hamyar-symptom-checker` از نسخهٔ ۰.۱.۱ روی سایت هست | روی همان صفحه، زیر پیام، پیوند **«جایگزینی نسخهٔ فعلی با نسخهٔ بارگذاری‌شده»** را بزنید. حذف افزونه لازم نیست. |
| «بارگذاری فایل ناموفق بود» یا خطای ۴۰۳/۴۰۶ از هاست | فایروال هاست (ModSecurity) یا افزونهٔ امنیتی، آپلود ZIP حاوی PHP را رد کرده | از پشتیبانی هاست بخواهید قاعده را برای این فایل بردارند، یا پوشهٔ افزونه را از «مدیر فایل»/FTP با محتوای ZIP عوض کنید |
| «این افزونه به دلیل ناسازگاری فعال نشد» (بدون کلمهٔ «مشکل جدی») | نسخهٔ PHP کمتر از ۸.۰ | نسخه را در «ابزارها ← سلامت سایت ← اطلاعات ← سرور» ببینید؛ هدر افزونه PHP ۸.۰ و وردپرس ۶.۴ می‌خواهد |

پیام قرمز **«این افزونه به دلیل داشتن مشکل جدی، فعال نشد»** هیچ‌کدام از این سه حالت نیست: یعنی ZIP سالم نصب شده و کد در لحظهٔ فعال‌سازی خطای مرگبار داده است — همان چیزی که ۰.۱.۲ برای آن گزارش خطا می‌سازد (بخش بعدی).

## اگر باز هم فعال نشد

این حالت یعنی خطا **قبل از اجرای کد افزونه** رخ داده (فایل PHP ناقص یا ناسازگاری بنیادی). در این صورت:

1. **هیچ افزونه‌ای را حذف نکنید.** مشکل از افزونه‌های دیگر نیست.
2. ایمیل مدیر سایت را ببینید؛ وردپرس هنگام خطای فعال‌سازی ایمیلی با عنوان «Your site is experiencing a technical issue» می‌فرستد که **متن خطا، فایل و شمارهٔ خط** در آن است. همان چند خط را بفرستید.
3. اگر ایمیل نبود: در `wp-config.php` این دو خط را موقتاً اضافه کنید، فعال‌سازی را تکرار کنید و محتوای `wp-content/debug.log` را بفرستید:
   ```php
   define( 'WP_DEBUG', true );
   define( 'WP_DEBUG_LOG', true );
   ```
   بعد از گرفتن خطا، این دو خط را بردارید.
4. اگر خطا از نوع «Allowed memory size» بود، `WP_MEMORY_LIMIT` را روی `256M` بگذارید و دوباره تلاش کنید.

## دربارهٔ حذف افزونه‌های قبلی

**نه — چیزی حذف نکنید.**

- «همیار جراحی — اصلاح هم‌خط‌های پروفایل بیماری» و «همیار جراحی — بررسی همگام‌سازی پروفایل» ابزار نگهداری و شاهد اصلاح فایل پروفایل‌ها هستند و باید بمانند.
- «راهنمای علائم» نسخهٔ ۰.۵.۰ نسخهٔ قدیمی و جدا از این ابزار است؛ فعال یا غیرفعال‌بودنش روی این افزونه اثر ندارد. اگر بعداً بخواهید بازنشسته‌اش کنید، تصمیم جداگانه و با پشتیبان است.
- LiteSpeed Cache / Clarity / Site Kit / UpdraftPlus به این خطا ربطی ندارند؛ فقط ممکن است کش را پاک‌کردن لازم شود.
