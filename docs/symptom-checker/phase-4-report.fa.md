# گزارش فاز ۴ — افزونه و برگهٔ مستقل وردپرس

**تاریخ:** ۳۱ اکتبر ۲۰۲۶ · **وضعیت:** افزونهٔ پیش‌نمایش، در وردپرس محلی آزموده شد · **انتشار:** هیچ (نه روی site زنده، نه لینک عمومی)

این فاز همان رابط فاز ۳ را داخل وردپرس می‌آورد: یک افزونهٔ مستقل که یک **برگهٔ پیش‌نویس** با قالب اختصاصی می‌سازد، موتور و بستهٔ دانش را از داخل بستهٔ خودش بارگذاری می‌کند و فقط برای موضوع‌هایی لینک مقاله می‌سازد که **یک** نوشتهٔ منتشرشدهٔ متناظر دارند.

## قراردادهای افزونه

1. **برگهٔ پیش‌نویس، نه عمومی.** با فعال‌سازی یک برگهٔ `draft` با نامک `symptom-checker` ساخته می‌شود؛ اگر برگه‌ای با همین نامک از قبل باشد، فقط شناسه‌اش ثبت می‌شود و **هیچ محتوا یا وضعیتی بازنویسی نمی‌شود**.
2. **قالب اختصاصی، بدون شورت‌کد و iframe.** دارایی‌ها فقط در همان برگه `enqueue` می‌شوند؛ برگه‌های دیگر نه CSS ابزار را می‌گیرند نه JS آن را.
3. **`noindex, nofollow`** روی همان برگه، حتی اگر اشتباهی منتشر شود.
4. **بدون ذخیره‌سازی و بدون endpoint.** هیچ REST route، هیچ جدول، هیچ `$_GET/$_POST` و هیچ تماس شبکه‌ای در افزونه نیست؛ پاسخ‌ها در حافظهٔ مرورگر می‌مانند.
5. **نگاشت محافظه‌کارانهٔ مقاله.** فقط `disease` با وضعیت `publish` و نامک **دقیقاً برابر**؛ صفر یا چند تطبیق ⇒ هیچ لینکی ساخته نمی‌شود و رویداد `hj_sc_topic_link_unresolved` برای عیب‌یابی اجرا می‌شود. تطبیق حدسی از شباهت عنوان ممنوع است.
6. **کد ماژول فقط برای فایل خودش.** فیلتر `script_loader_tag` رشتهٔ تگ را **اصلاح** می‌کند نه جایگزین؛ این نکته در آزمون وردپرس کشف شد (جایگزینی، اسکریپت درون‌خطی پیکربندی را حذف می‌کرد).
7. **راه برگشت بدون حذف داده:** پیش‌نویس‌کردن برگه یا غیرفعال‌کردن افزونه؛ هیچ‌کدام برگه یا محتوای دیگری را پاک نمی‌کند.
8. **پیکربندی امن:** JSON با `JSON_HEX_TAG|JSON_HEX_AMP|JSON_HEX_APOS|JSON_HEX_QUOT` ساخته می‌شود تا لینک مخرب نتواند از `</script>` بیرون بزند (آزمون منفی دارد).

## آزمون‌ها و آنچه هرکدام اثبات می‌کند

```sh
python3 tools/symptom-checker-plugin/build_package.py --check          # بسته با منابع یکی است
python3 -m unittest discover -s tools/symptom-checker-plugin -p 'test_*.py'   # ۱۱/۱۱
node tools/symptom-checker-plugin/php-checks.mjs                       # ۱۲ سناریو / ۸۵ بررسی (PHP 8.3 واقعی)
node tools/symptom-checker-plugin/check-wordpress.mjs                  # ۲۸/۲۸ در WordPress 6.8.3
cd symptom-checker/ui && node --test                                   # ۱۲/۱۲
cd symptom-checker/engine && node --test                               # ۳۸/۳۸
python3 -m unittest discover -s tools/symptom-checker-audit -p 'test_*.py'    # ۲۵/۲۵
```

### جزئیات آزمون وردپرس

- WordPress 6.8.3 (از `codeload.github.com`، با بررسی SHA-256)، PHP 8.5، SQLite، یک worker، سایت دورریختنی.
- فاز اول: افزونه فعال می‌شود و برگه **پیش‌نویس** می‌ماند ⇒ درخواست بی‌نام به آن **۴۰۴** است.
- فاز دوم: مالک برگه را منتشر می‌کند ⇒ صفحه ۲۰۰، قالب افزونه، `noindex, nofollow`، تنها یک `type="module"`، پیکربندی درون‌خطی قبل از آن، و هر ۹ دارایی بسته ۲۰۰.
- نگاشت: نوشتهٔ منتشرشدهٔ `appendicitis` لینک گرفت؛ نوشتهٔ **پیش‌نویس** `kidney-stones` نه؛ صفحهٔ اصلی و صفحهٔ مقاله تغییری نکردند.

## چه چیزی تأیید نشده است

- ❌ **سایت زنده.** هیچ‌چیز روی hamyarjarahi.ir نصب یا فعال نشده است. قالب فرزند، افزونه‌های واقعی، کش، CDN، فهرست نامک‌های واقعی مقاله‌ها و نوع محتوای `disease` در محیط واقعی آزموده نشده‌اند.
- ❌ **مرورگر واقعی، موبایل و صفحه‌خوان.** همهٔ بررسی‌های رابط در jsdom است؛ چیدمان، RTL، تداخل CSS قالب و دسترس‌پذیری واقعی بازبینی انسانی لازم دارد (F3-08).
- ❌ **اعتبار بالینی و دقت.** داده همان `0.1.0-draft` با `pending_team_review` است.
- ❌ **ناسازگاری نسخه‌ها.** آزمون روی PHP 8.3 (بسته) و 8.5 (Playground) انجام شد؛ PHP 8.0/8.1 و WordPressهای قدیمی‌تر آزموده نشدند.
- ❌ **نگاشت واقعی مقاله‌ها.** رفتار کد آزموده شد، نه درستی نامک‌های `article_slug` بستهٔ دانش در برابر سایت زنده (این همان F1-07 است).
- ❌ **کش و صف.** رفتار با افزونه‌های کش صفحه/شیء و پاک‌سازی کش پس از انتشار یا تغییر نوشته آزموده نشده است.

## گام بعدی — فاز ۵

1. آزمون ایمنی و حریم خصوصی: پاسخ متناقض/نامعلوم، موارد خارج از پوشش، رفتار شبکه و ابزارهای تحلیل، قطع سرویس و بازگشت.
2. بازبینی انسانی رابط در مرورگر واقعی، موبایل و صفحه‌خوان روی همین بسته.
3. تأیید محتوایی تیم (F1-06) و تثبیت نگاشت مقاله‌های زنده (F1-07) تا `article_slug`ها در محیط واقعی بررسی شوند.
4. آزمون نصب و بازگشت روی یک کپی از سایت واقعی (نه سایت زنده) در فاز ۶، با پشتیبان و تأیید صاحب سایت.

**مرز:** این گزارش ادعای آمادگی انتشار ندارد. افزونه در وردپرس محلی و در همان شرایط آزمون کار می‌کند؛ دربارهٔ سایت واقعی، ظاهر، کش و محتوای مقاله‌ها هیچ ادعایی نمی‌شود.
