# کارگاه دادهٔ ابزار علائم

این پوشه «workspace» نویسندگی است: هر چیزی که اینجاست، به بستهٔ دانش اضافه می‌شود؛ هر چیزی که نیست، در بستهٔ پایه می‌ماند. فقط `tools/symptom-checker-author/author.py` اجازه دارد این‌ها را به بسته تبدیل کند.

## ساختار

```text
docs/symptom-checker/authoring/
├── sources/        منبع بالینی: id، عنوان، نشانی، accessed، review_status
├── symptoms/       نشانهٔ تازه: id با پیشوند خوشه (abd.*) و برچسب فارسی
├── questions/      پرسش تازه: ask_order، visibility، options با evidence[]
├── conditions/     بیماری: name_fa، profile_ref، profile[] با level و source_refs
├── overrides.json  قاعده‌هایی که ماتریس نمی‌تواند بیان کند (مسیر/استثنا)
└── examples/
    └── cholecystitis/   مجموعهٔ پذیرش فاز ۳ — داده است، هنوز به workspace زنده ارتقا نیافته
```

هر فایل یک شیء JSON است؛ نام فایل = شناسه (مثلاً `conditions/chole.json`).

## افزودن یک بیماری (همان مسیری که فاز ۳ آزمود)

```sh
A=tools/symptom-checker-author/author.py

# ۱) اسکلت بیماری + فهرست نشانه‌های موجود
python3 $A add-condition <id> --name «نام فارسی»

# ۲) منبع بالینی را ثبت کنید (بدون منبع، ردیف پروفایل خطا می‌دهد)
python3 $A add sources --file <منبع.json>

# ۳) نشانهٔ تازه (اگر لازم است) و پرسشی که آن را می‌پرسد
python3 $A add symptoms  --file <نشانه.json>
python3 $A add questions --file <پرسش.json>
#    ↳ سپس برای همان پرسش، خط راهنما در symptom-checker/ui/question-help.js
#      (هر گزینه یک جمله؛ خط «نمی‌دانم» باید برچسب واقعی همان گزینه را داشته باشد)

# ۴) پروفایل را کامل کنید: حداقل ۳ ردیف، حداقل یک typical، هر ردیف با source_refs
python3 $A validate
python3 $A overlap          # آیا با بیماری موجود قابل تفکیک است؟
python3 $A report           # چه چیزی پوشش ندارد؟
python3 $A build-bundle     # نسخهٔ minor بالا می‌رود؛ دروازهٔ موتور هم اجرا می‌شود
```

## قاعده‌های ثابت

- **فقط داده.** نه کد موتور، نه کد UI، نه فایل بسته دست‌کاری نمی‌شود. تغییر UI فقط همان یک بلوک متن راهنما است.
- **هر ادعا منبع دارد.** `source_refs` روی هر ردیف پروفایل و هر گزینه؛ منبع تازه با `accessed` (تاریخ واقعی) و `review_status`.
- **محتوای تازه `pending_team_review`.** هیچ‌چیز «تأییدشده» نامیده نمی‌شود تا تیم بررسی کند.
- **بدون عدد.** هیچ احتمال، درصد، امتیاز یا رتبه‌ای در داده نیست؛ «هم‌پوشانی نشانه‌ها» شاهد است، نه اثبات.
- **حذف ممنوع.** بیماری یا پرسش موجود پاک نمی‌شود؛ اگر لازم شد سطح ردیف `not_expected` می‌شود.
- **هر نشانهٔ تازه، پرسش می‌خواهد.** نشانه‌ای که هیچ گزینه‌ای گزارشش نمی‌کند، برای بیماری تازه خطاست (برای محتوای قدیمی به ارث رسیده، هشدار و `not_covered`).

## چرا `examples/` جدا است؟

مجموعهٔ پذیرش باید ثابت بماند تا هر بار بتوان نشان داد «همین داده، همین بسته را می‌دهد». تا وقتی تیم محتوای کوله‌سیستیت را تأیید نکرده، این پوشه در `examples/cholecystitis/` می‌ماند و به workspace زنده منتقل **نمی‌شود**؛ انتقال، تصمیم جداگانه‌ای است.
