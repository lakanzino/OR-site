# بازگردانی سایت پس از نصب اشتباهی 0.9.2

> **قانون اول (همیشه): هر فایلی که برای صاحب سایت فرستاده می‌شود، فقط با لینک قابل دانلود از گیت‌هاب یا گوگل درایو ارائه می‌شود. مسیر محلی یا فایل بی‌لینک ارسال نمی‌شود.**


**نشانه:** بعد از به‌روزرسانی، طراحی/بخش‌های پیشخوان (از جمله بخش ارتباط با GitHub) غیب شدند.
**علت:** بستهٔ `child-v0.9.2` فقط «کانال به‌روزرسانی» را اضافه کرده بود و کد ظاهری‌اش پایهٔ **0.4.0** بود؛ نصب آن، نسخهٔ 0.9.1 را با 0.4.0 جایگزین کرد.
**خبر خوب:** هیچ محتوایی (نوشته/برگه/تصویر/تنظیمات) از بین نمی‌رود — فقط فایل‌های قالب عوض شده‌اند و 0.9.1 کامل در Drive هست.

## بازگردانی (۳ دقیقه، بدون از دست رفتن محتوا)

### راه اول — File Manager هاست (مطمئن‌ترین)
1. `lax-theme-child-install-0.9.1.zip` را از Google Drive، پوشهٔ **۰۲-قالب-فرزند** دانلود کنید.
2. File Manager هاست → `public_html/wp-content/themes/`
3. پوشهٔ `lax-theme-child` را به `lax-theme-child-ron` تغییر نام دهید (حذف نکنید).
4. ZIP 0.9.1 را در `themes/` آپلود و Extract کنید تا پوشهٔ `lax-theme-child` دوباره ساخته شود.
5. سایت را باز کنید؛ اگر 200 بود، تب پیشخوان را ببندید و باز کنید.
6. اگر همه‌چیز سالم بود، پوشهٔ `lax-theme-child-ron` را حذف کنید.

### راه دوم — از داخل پیشخوان (اگر فرانت سالم است)
1. نمایش → پوسته‌ها → «افزودن پوستهٔ جدید» → «بارگذاری پوسته».
2. ZIP را انتخاب کنید. اگر خطای «پوشه از قبل وجود دارد» داد، اول باید پوشهٔ فعلی را (از File Manager) تغییر نام دهید؛ وردپرس اجازهٔ جایگزینی پوستهٔ فعال را نمی‌دهد.

> اگر سایت به‌خاطر نبودن پوشهٔ فعال خطای مهلک داد، از File Manager پوشه را برگردانید؛ محتوا و دیتابیس دست‌نخورده‌اند.

## چطور مطمئن شویم برگشته
- نمایش → پوسته‌ها → جزئیات `Lax Theme Child` → **Version: 0.9.1**
- خط اول `wp-content/themes/lax-theme-child/style.css` → `Version: 0.9.1`
- بخش‌های ارتباط با GitHub در پیشخوان دوباره دیده شوند.

## چرا نوتیفیکیشن «نسخهٔ جدید» را ندیدید
احتمال‌ها به ترتیب احتمال:
1. **نام پوشهٔ قالب** روی هاست `lax-theme-child` نیست (مثلاً `lax-theme-child-install-0.9.1`). تطبیق به اسلاگ پوشه وابسته است.
2. این سایت هاست امن‌شده دارد و `api.github.com` یا `raw.githubusercontent.com` بسته است؛ در این حالت هیچ درخواستی جواب نمی‌گیرد.
3. کش / قفل نصب: `DISALLOW_FILE_MODS` یا افزونهٔ مدیریت هاست.
4. پوستهٔ فعال اصلاً `lax-theme-child` نبوده است.
