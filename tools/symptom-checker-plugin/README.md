# ساخت و آزمون بستهٔ وردپرس دستیار نشانه‌ها

این پوشه بستهٔ نصب افزونهٔ [`plugins/hamyar-symptom-checker/`](../../plugins/hamyar-symptom-checker/) را از منابع مخزن می‌سازد و آن را در چند لایه می‌آزماید. یک نسخه از رابط و موتور وجود دارد؛ فایل‌های کپی‌شده دستی در افزونه نگه داشته نمی‌شوند.

## ساخت بسته

```sh
python3 tools/symptom-checker-plugin/build_package.py            # می‌سازد: releases/hamyar-symptom-checker-<نسخه>.zip
python3 tools/symptom-checker-plugin/build_package.py --check    # بستهٔ موجود باید با منابع یکی باشد
python3 tools/symptom-checker-plugin/build_package.py --json     # خلاصهٔ ماشین‌خوان (نسخه، هش، فهرست دارایی‌ها)
```

ساخت تکرارپذیر است (زمان ورودی‌های zip ثابت) و هش هر دارایی در `assets/SOURCES.json` داخل بسته ثبت می‌شود؛ `--check` اگر بسته با منبع فرق کند یا فایل اضافه/کم داشته باشد خطا می‌دهد.

## آزمون `python` (بدون وابستگی)

```sh
python3 -m unittest discover -s tools/symptom-checker-plugin -p 'test_*.py' -v
```

ساختار بسته، برابری بایت‌به‌بایت دارایی‌ها با منبع، تکرارپذیری ساخت، پوشش مانیفست و کارکرد دروازهٔ مغایرت را می‌سنجد.

## آزمون PHP (واقعی، با PHP 8.3 در WebAssembly)

```sh
npm install --no-save @php-wasm/node @php-wasm/universal
node tools/symptom-checker-plugin/php-checks.mjs
```

بسته ساخته و باز می‌شود، سپس در PHP واقعی:

- هر فایل PHP با `token_get_all(..., TOKEN_PARSE)` تجزیه می‌شود؛
- سناریوهای فعال‌سازی، نگاشت، پیکربندی، فرار `</script>`، بارگذاری دارایی‌ها، `robots`، قالب و نگهبان‌ها با استاب‌های وردپرس اجرا می‌شوند.

این آزمون منطق خود افزونه را اثبات می‌کند، نه رفتار وردپرس را.

## آزمون در وردپرس واقعی (Playground محلی)

```sh
node tools/symptom-checker-plugin/check-wordpress.mjs
```

مراحل: ساخت بسته، دانلود WordPress 6.8.3 از GitHub با بررسی SHA-256، نصب WordPress Playground CLI و jsdom در پوشهٔ موقت، دو بار بالا آوردن سایت (یک بار برگه هنوز پیش‌نویس، یک بار منتشرشده) و سپس:

- برگهٔ پیش‌نویس برای بازدیدکننده ۴۰۴ است و فقط با انتشار در دسترس قرار می‌گیرد؛
- صفحه با قالب افزونه رندر می‌شود، `noindex, nofollow` است و فایل ورودی با `type="module"` و پیکربندی درون‌خطی قبل از آن چاپ می‌شود؛
- همهٔ دارایی‌های بسته ۲۰۰ می‌دهند و صفحه‌های دیگر سایت هیچ‌کدام از این دارایی‌ها را بار نمی‌کنند؛
- نگاشت مقاله: نوشتهٔ منتشرشده لینک می‌گیرد، نوشتهٔ پیش‌نویس نه؛
- رابط بسته‌شده در jsdom روی همان URLهای زنده اجرا و پرسش‌نامه پاسخ داده می‌شود و کارت‌ها، هشدار و لینک بررسی می‌شوند.

آزمون به `npm` و دسترسی شبکه به `registry.npmjs.org` و `codeload.github.com` نیاز دارد و همه‌چیز را در پوشهٔ موقت می‌سازد. سایت Playground **جای سایت زنده نیست** و قالب، افزونه‌ها، کش و پایگاه‌دادهٔ واقعی را نمایندگی نمی‌کند.

## مرز ادعاها

هیچ‌کدام از این آزمون‌ها اعتبار بالینی، دقت یا ایمنی را نمی‌سنجد و جای بازبینی انسانی در سایت واقعی را نمی‌گیرد. نتیجهٔ هر اجرا در [گزارش فاز ۴](../../docs/symptom-checker/phase-4-report.fa.md) ثبت می‌شود.
