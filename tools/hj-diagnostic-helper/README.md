# HJ Diagnostic Helper — مرحلهٔ یک، فقط‌خواندنی

افزونهٔ مستقل و موقت **نسخهٔ ۰٫۱٫۰** برای مدیر، به منظور مشاهده JSON ساختار جدولی که پل رأی افزونه همیار پزشک‌ها شناسایی می‌کند. این نسخه ابزار درج یا حذف داده، مدیریت رأی، شمارش بازدید/کلیک یا نوبت‌دهی نیست و نمونه واقعی یا ساختگی در سایت وارد نمی‌کند. فعال‌سازی افزونه خود رویداد تغییر فهرست افزونه‌های فعال در وردپرس است؛ سایر افزونه‌ها/هوک‌ها نیز ممکن است در همان درخواست عملیات داشته باشند. «بدون ریسک» یا عدم تغییر کل دیتابیس ادعا نمی‌شود.

## گزارش

فقط مدیر دارای `manage_options` و فقط GET در «ابزارها ← گزارش تشخیصی رأی» به JSON داخل textarea دسترسی دارد. افزونه روی metadata با نام جدول اعتبارسنجی‌شده `SHOW COLUMNS` و `SHOW INDEX` اجرا می‌کند. ساختار در حد نام ستون‌ها، گروه نوع یا نوع ساده، nullable، نشانگر کلید، نگاشت چهار نقش پل و ستون‌های PK است. نام کامل جدول/پیشوند، پیش‌فرض‌ها، توضیح ستون‌ها و مقادیر تعریف‌شده در enum/set عمداً حذف می‌شوند. هیچ SELECT از ردیف‌های جدول رأی، شناسه پزشک/رأی‌دهنده، IP، متن نظر، متای پزشک یا کد ملی در خود گزارش خوانده نمی‌شود. خروجی `null` یا `unknown` یعنی نامعلوم یا خطای بررسی، نه صفر یا نبود قطعی. یکتایی PK و وجود ستون status اثبات معنا یا قابلیت امن تغییر نیست. `SHOW COLUMNS` و `SHOW INDEX` نیازمند دسترسی DB هستند. رفتار فیلترها/افزونه‌های نصب‌شده دیگر خارج از کنترل این افزونه است.

نام ستون‌ها ممکن است اطلاعات ساختار داخلی را فاش کند: پیش از فرستادن JSON به هر شخص/سرویس آن را بررسی و موارد حساس را حذف کنید؛ هرگز فایل wp-config، رمز، توکن، IP، داده بیماران یا داده پروفایل نفرستید. این گزارش شمار رأی‌ها یا مقادیر واقعی status را نمی‌دهد.

## نصب/جمع‌آوری/پاکسازی

صرفاً پس از تأیید تحویل، تهیه پشتیبان فایل و DB قابل‌بازیابی و بررسی، مدیر ZIP مستقل بدون پوشه tests را از پیشخوان نصب و فعال می‌کند. افزونه اصلی باید فعال باشد. سپس از ابزارها، متن JSON را کپی و در صورت تمایل پس از بررسی ارسال می‌کند؛ نیازی به دکمه‌های دمو یا ثبت رأی وجود ندارد. پس از دریافت، مدیر می‌تواند خود افزونه کمکی را از فهرست افزونه‌ها غیرفعال و سپس پاک کند. این افزونه داده یا جدول خاص خود را ایجاد نمی‌کند، اما پاک‌کردن فایل آن آثار کلی افزونه‌های دیگر یا بازگردانی DB وردپرس را تضمین نمی‌کند. در هر وضعیت غیرمنتظره متوقف شوید و پشتیبان را خودسرانه بازنگردانید.

## آزمون‌ها

- `HJ_PHP_WASM_ROOT=/tmp/or-site-php node tools/hj-diagnostic-helper/run-stub-test.mjs` با PHP WASM و stub، بدون DB واقعی.
- `python3 tools/hj-diagnostic-helper/tests/test_package.py` محتوای ZIP را در برابر فایل اجرایی و حذف تست‌ها کنترل می‌کند.
- `tests/setup-vote-wp.php` و `tests/diagnostic-wp.php` مخرب‌اند، فقط در دیتابیس WordPress کاملاً دورریختنی، جدا از سایت یا بکاپ واقعی. workflow GitHub MariaDB نیز با DB خالی و کانتینر دورریختنی عمل می‌کند. `SHOW INDEX` ممکن است در سازگاری SQLite نامعلوم باشد؛ رفتار MariaDB جداگانه آزموده می‌شود.
